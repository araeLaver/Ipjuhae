# 워크로그 2026-09-22 — 홈페이지를 다시 짓고, 홈을 덮고 있던 버그를 잡았다

## 먼저 확인한 것: 구글 플레이에 빠른 길은 없다

"실제적으로 빨리 출시"를 찾아 콘솔을 직접 열어봤다.

```
프로덕션     →  잠김 (테스터 12명 × 14일)
공개 테스트   →  잠김 (같은 조건)
```

**공개 테스트까지 막혀 있다.** 우회로가 없다는 뜻이다. 12명을 오늘 채워도
2주 뒤에야 신청이고 거기에 심사가 붙는다. 그래서 "빨리 출시"의 답은
플레이스토어가 아니라 **웹을 제대로 만들어 지금 쓰게 하는 것**이 됐다.

## 홈이 앱 설치 안내를 보여주고 있었다

`www.ipjuhae.com/` 을 열면 「폰에 설치해서 쓰기」가 나왔다. `/install`(당시 `/app`)의
내용이다. 제목도 「앱으로 쓰기」였고 `| 입주해` 접미사가 빠져 있었다.

**원인은 라우트 이름이다.** 앱 디렉터리(`app/`) 안에 `app`이라는 세그먼트를 만들어
`app/app/page.tsx`가 됐다. 배포 환경에서 Next가 `app/app/`을 앱 루트로 잡으면서
그 페이지가 `/`로 서빙됐고, 루트 레이아웃도 안 붙었다(제목 접미사가 빠진 이유).

**로컬에서는 멀쩡했다.** 로컬 `next start`로는 `/`가 정상이었고 프로덕션에서만 터졌다.
빌드 출력의 라우트 표에도 `/`는 제대로 찍혀 있었다.

`/install`로 이름을 바꿔 해결했다. 교훈은 하나다. **앱 디렉터리 안에 `app`이라는
이름의 세그먼트를 두지 않는다.**

## 홈페이지를 다시 지었다

전에는 첫 화면이 커뮤니티 게시판 그 자체였다. 글쓴이가 운영자 혼자인 게시판은
처음 온 사람에게 빈 방으로 보인다. 컨셉을 **"계약 전에 확인하는 곳"** 으로 잡고
읽는 곳이 아니라 확인하는 곳으로 순서를 바꿨다.

| 순서 | 무엇 | 역할 |
| --- | --- | --- |
| 1 | 계약서에 도장 찍기 전에, 보증금부터 확인하세요 | 3초 안에 무슨 사이트인지 |
| 2 | 보증금 점검하기 | 바로 써볼 것 |
| 3 | 입주해가 정리한 것 (등기부 12편, 임대인 노트 6편) | 읽을 것 |
| 4 | 알아두면 보증금을 지키는 제도 | 알아볼 것 |
| 5 | 계약 전에 물어보는 곳 | 물어볼 것 |
| 6 | 앱과 테스터 | 계속 쓸 것 |

글 목록은 **서버에서 읽는다.** 브라우저에서 불러오면 검색엔진에는 빈 화면이
색인된다. 글 하나하나가 유입 경로인데 그러면 소용이 없다.

`/community`를 게시판으로 되돌렸다. `/`로 넘기던 리다이렉트는 첫 화면이
게시판이던 시절의 흔적이다.

## 제도 페이지 (`/policy`)

"실시간 정책"을 붙이려 했는데 자동 수집이 전부 막혔다.

```
korea.kr RSS       404 (RSS 페이지 자체가 사라짐)
국토부 보도자료      307 차단
HUG 공지            406 차단
공공데이터포털 API   인증키 필요
```

**자동 수집인 척하지 않기로 했다.** 확인한 것을 손으로 정리하고
항목마다 **출처 링크와 확인일**을 함께 싣는다. 제도는 바뀌니까
언제 확인한 정보인지 모르면 읽는 사람이 판단할 수 없다.

넣은 것은 다섯 가지다. 소액임차인 최우선변제(지역별 금액표 포함),
전입신고와 확정일자, 전세보증금반환보증, 임차권등기명령, 전세사기 피해 지원.

**HUG 가입 요건 비율은 일부러 숫자를 적지 않았다.** 출처마다 80·90·140퍼센트로
값이 갈렸다. 틀린 기준을 보고 계약하면 되돌릴 수 없다. 공식 창구 세 곳만 걸었다.
`lib/policies.ts`에 규칙으로 적어 뒀다. **확인한 것만 숫자를 적는다.**

## 홈이 빈 채로 굳었다

배포했는데도 홈에 "글을 불러오지 못했습니다"가 계속 떴다. API는 정상이라
런타임 DB는 멀쩡했다.

`revalidate`로 미리 만들게 해 뒀는데 **빌드 시점에는 DB가 없어서** 빈 결과가
그대로 굳은 것이다. 재검증으로도 안 풀렸다. `force-dynamic`으로 바꿨다.
첫 방문자가 빈 홈을 보는 건 캐시로 아끼는 것보다 비싸다.

같이 찾은 것 하나. 목록에 쓰는 건 본문 첫 줄뿐인데 200건의 본문을 통째로
실어 보내고 있었다. SQL에서 300자로 잘랐다.

DB가 **실패**가 아니라 **매달리면** 서버 컴포넌트가 끝나지 않아 HTML 스트림이
열린 채 남는다. try/catch로는 못 잡는다. 2.5초 제한을 따로 걸었다.
