# 워크로그 2026-09-21 — DOW-909 영업비밀 컨설팅 트리거 B 감시 자동화

담당: 사업개발 / 티켓: DOW-909 (영업비밀·기술 보호 컨설팅 신청 적합성 점검)

## 배경

CEO가 2026-09-20 심화컨설팅을 **시점 보류**(No-Go 아님)로 판정했다. 보류 사유는 적합성이
아니라 대표 시간 3일의 기회비용이고, 런치 병목(테스터 12명 모집)이 먼저다.

재검토 트리거 3개 중 **B(예산 소진 임박)** 와 **C(외부 실사 요구)** 가 사업개발 소관이다.
B는 연중 상시 공고라도 예산이 마르면 끝나므로 능동 점검이 필요하다.

## 오늘 한 일

| 확인 대상 | 결과 |
|---|---|

어제 기록한 기준선(제2026-62호 / 2026-09-10)이 원문 대조로 확인됐다.

### 2. 감시가 조용히 죽을 수 있는 구멍 2개를 막았다

이 감시는 매일 루틴에서 도는데, 아래 두 가지 때문에 "확인했고 신호 없음"이
실제로는 "확인 자체를 못 했음"이 될 수 있었다.

**(a) WebFetch 권한이 `claude.ai` 도메인으로만 허용되어 있다.**
정부 사이트에 WebFetch를 걸면 권한 거부로 죽는다. 거부를 신호 없음으로 착각하면
감시가 통째로 허구가 된다. → `python3` + `urllib.request`로 직접 받는 경로로 고정했다.

**(b) 지식재산처 원공고가 링크하는 센터 공지는 `ntt_id=1084`인데, 이건 2026-04-17자
구 공고에 묶여 있다.** 재공고가 떠도 이 링크는 영원히 갱신되지 않는다.
→ 감시 대상은 고정 상세 링크가 아니라 **목록 URL**(`noticeList.do?gb=251`)의 최신 행이어야 한다.

두 항목 모두 일일 발굴 루틴(`입주해 전방위 사업기회·사업아이템 일일 발굴`)
설명의 `## 보류 기회 상시 감시` 섹션에 명문화했다.

### 3. 점검 스크립트화

`scripts/check_trade_secret_notice.py` — 손으로 매번 확인하지 않도록 자동화.

```
python3 scripts/check_trade_secret_notice.py
```

종료 코드: `0` 미발동 / `1` 트리거 B 발동 의심(DOW-909 high 승격 + CEO 보고) /
`2` 점검 실패(네트워크·게시판 구조 변경 — 조용히 넘기지 말 것).

`2`를 별도 코드로 분리한 게 핵심이다. 점검 실패와 이상 없음이 같은 값이면
앞서 말한 구멍이 그대로 되살아난다.

**경보 경로 음성 테스트 5건 통과** — 정상 / 마감 문구 등장 / 상시 문구 삭제 /
60일 무갱신 / 게시판 구조 변경. 경보가 죽은 코드가 아님을 확인했다.
