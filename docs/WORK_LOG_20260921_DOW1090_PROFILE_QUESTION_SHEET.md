# 워크로그 2026-09-21 — DOW-1090 회사 기본 프로필: 보드 질문 8개 → 2개 압축

담당: 사업개발
티켓: DOW-1090 (회사 기본 프로필 1건 상시 유지 — 지원사업 판정 선행값 고정)

## 들어온 지시

CEO가 담당자 공란 상태였던 DOW-1090을 사업개발로 배정하면서 세 가지를 요구했다.

1. 미확인 값이 있어도 멈추지 말고 `확정/미확인`을 명시한 프로필로 조건부 판정을 돌릴 것
2. **사람이 답해야만 하는 항목만** 따로 목록으로 뽑아 올릴 것
3. 한 번에 묻고 반복해서 묻지 않을 것

1번과 3번은 이미 프로필 4장(운영 규칙)과 일일 발굴 루틴에 들어가 있다. 이번 작업의 실질은 2번이다.

## 한 것

### 프로필 문서 7장 신설 (revision 3 → 4)

`DOW-1090 profile` 문서에 `## 7. 보드 회신 시트 — 사람만 답할 수 있는 항목`을 추가했다.

핵심 판단: **8개 값은 서로 독립이 아니다.** 의존관계를 풀면 보드 질문은 2개로 줄어든다.

- **Q1** 경기도와의 연결고리 (`거주/사업장/재학/재직/없음`) → 값 8. 게이트 2026-10-08
- **Q2** 대표자 본인 명의 사업자등록 보유 여부 (`없음 / 입주해 1개뿐 / 2개 이상`) → 값 1·3 동시 확정
- **Q3~Q5** 설립일·직원수·매출은 **Q2가 `있음`일 때만** 묻는다

Q2가 `없음`이면 값 2·4·5·6·7이 연쇄로 결정되어 **8개 중 7개가 한 번에 끝난다.**

### 질문의 형태를 라벨에서 사실로 바꿨다

기존 1번은 `예비창업자 / 개인사업자 / 법인` 중 고르는 질문이었다. `예비창업자`는 사실이 아니라 공고가 부여하는 자격 라벨이고, 공고 대부분이 이를 `접수마감일 기준 사업자등록 미보유자`로 정의한다. 라벨로 물으면 답하는 쪽이 자기 상태를 공고 용어로 번역해야 하고, 그 번역이 틀리면 판정 전체가 틀린다.

사실(`사업자등록이 있는가`)로 물으면 번역이 필요 없고, 같은 답이 값 3(대표자 보유 타 사업자)까지 채운다. 다른 사업자를 보유한 사람은 정의상 예비창업자가 아니므로 두 값은 애초에 같은 사실의 두 얼굴이었다.

### 연쇄 결정의 근거를 확인된 사실과 판단으로 분리했다

기관 페이지를 직접 받아 대조했다(`.dow1090_verify.py`, 일회성 확인용이라 커밋하지 않음).

| 값 | 결론 | 등급 |
|---|---|---|
| 4 창업기업 확인서 | 필수서류에 `사업자등록증명`이 **공통(개인/법인)**으로 명시 → 사업자등록 없으면 리드타임과 무관하게 발급 불가 | **확인된 사실** (cert.k-startup.go.kr 확인절차 페이지) |
| 5 중소기업 확인서 | SMINFO 발급절차가 `개인사업자`·`법인사업자` 두 유형뿐, 예비창업자 경로 없음 | **판단** — "예비창업자 불가" 명시 조항은 기관 페이지에 없음 |
| 6 직원수 / 7 매출 | 사업자등록이 4대보험 사업장 가입·사업 매출의 선행조건 | **판단** |

확인된 사실과 판단을 섞지 않고 문서·댓글 양쪽에 등급을 표기했다. 6장에서 "확인 불가는 숫자로 적지 않는다"고 세운 기준과 같은 처리다.

## 상태

DOW-1090을 `in_review`로 CEO에게 넘겼다. 지시가 "저에게 올려 주세요"였으므로 보드 전달 여부는 CEO 판단이다. 회신이 오면 사업개발이 값 테이블을 갱신하고 걸린 기회를 재판정한다.

회신이 없어도 멈추지 않는다.

- Q1: 2026-10-08 경과 시 값 8을 `없음`으로 간주하고 지역요건 없는 창구로 전환
- Q2: 마감 없음. 미확인 동안 `창업기업 확인서 필수` 공고는 `사업자등록 있으면 조건부 Go / 없으면 No-Go` + D-12영업일 규칙으로 판정 선발행
