# 후보 집 저장·비교·확인 기록

## 구현

- `/check`에서 결과를 본 뒤 후보 별칭과 계산 입력을 이 브라우저에 저장. 최대 5개.
- 후보 두 개 이상이면 시세·보증금·근저당·선순위 보증금·부담 비율·시세대로 팔릴 때 여유/부족 비교.
- 후보별 고정 계약 전 확인 기록 4개 저장, 재방문 복원, 다시 점검, 개별 삭제.
- 저장 데이터 버전·금액 범위·체크 항목 검증. 손상·차단·용량 초과에는 실패 표시. 손상 데이터는 확인 후 초기화. 다른 탭에서 바뀐 저장 상태 반영.
- 금액·별칭·확인 상태·후보 ID는 서버에 보내지 않음. 다른 기기 동기화와 계정 연결 없음. 개인정보 안내에 로컬 저장·삭제 방식을 명시.
- 후보 저장·비교 조회·확인 기록 변경만 익명 동작으로 집계. 서버에서 로그인 조회를 건너뛰고 계정·세션·비허용 속성 제거. 기존 유입 태그만 허용.
- 관리자 30일 일별 표에 동작 횟수 추가. 고유 사용자 수·재방문율을 의미하지 않음.

## 검증

- typecheck 및 프로덕션 빌드 성공.
- 전체 test:ci: 988 passed, 13 skipped. 이후 추가한 익명 서버 처리 3개·다른 탭 변경 테스트를 관련 테스트로 검증. 최종 CI에서 전체 재확인 예정.
- 실제 로컬 프로덕션 Playwright: 두 후보 저장·비교, 확인 기록 저장, 새로고침 복원, 숫자 다시 점검, 삭제 pass. 계측 금액/별칭 유출 없음.
- 저장 차단·손상·개수 제한·복원·익명 서버 처리 회귀 테스트 포함.
- 브라우저 테스트 로컬 analytics는 가로채 검증. 운영 DB 저장 검증은 아님.

운영 반영과 실제 공개 브라우저 확인은 배포 완료 후 별도 기록한다. 기존 작업 체크아웃 보존. 질문 답변 담당자·응답 시간 운영은 이 기능과 별도이며 임의로 약속하지 않는다.
