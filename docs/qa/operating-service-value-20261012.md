# 운영·수익 서비스 개선 — 2026-10-12

사용자 요구: 회사의 운영·수익 서비스이므로 기능 배포만으로 활성화 완료라고 판단하지 않는다. 이전 홈 개편 이후 최신 main 68e02423 기준 별도 worktree에서 개선했다. 원본 checkout의 기존 변경은 보존했다.

## 이용자가 얻는 결과

- 가입 없는 보증금 점검과 후보 5개 비교의 계약 준비 기록을 텍스트로 내려받아 집 보기·상담 전에 읽을 수 있다.
- 후보·확인 기록을 JSON 백업으로 내려받고 다른 브라우저에서 복원할 수 있다. 기존 후보 교체는 확인 후 실행하며 손상·과대 파일은 거부한다.
- 파일에는 사용자가 입력한 금액과 후보 별칭이 포함됨을 안내한다. 서버에 업로드하지 않는다. 공유 링크는 기존처럼 금액·후보 없이 공개 점검 주소만 담는다.
- 준비 기록 요청·백업 복원·공유 링크 복사는 익명 행동으로 집계한다. 로그인 조회를 하지 않고 금액·후보·계정·기기 식별자를 기록하지 않는다.
- 공개 /service에서 무료 제공 범위, 기존 집주인 월 이용 플랜, 공식 고객 문의를 한곳에서 안내한다. 결제 설정이 없으면 유료 결제 준비 중으로 표시하고 무료 도구를 우선 제공한다. 기존 가격(베이직 19,900원/월, 프로 49,900원/월)을 유지했다. 신규 상담 상품·가격을 임의로 만들지 않았다.

## 결제·구독

- 결제 완료는 URL의 success=true로 주장하지 않는다. 서버가 로그인 계정 소유권, Stripe 결제 상태, 실제 활성 구독을 각각 확인한다. 결제 완료와 웹훅 반영 대기를 구분한다.
- 유료 결제는 키·두 Price ID·웹훅 설정이 있을 때만 진행한다. 운영에서는 live 키를 요구하며 test 이벤트로 운영 유료 권한을 주지 않는다.
- 판매 가격·통화 KRW·월 주기·활성 가격이 서버의 플랜 정보와 다르면 결제를 열지 않는다.
- 기존 구독은 결제 관리 포털로 연결한다. 로컬 구독만 무료로 바꾸고 외부 정기결제가 계속 청구되는 경로를 막았다.
- 계정별 DB 트랜잭션 잠금으로 Checkout 생성 클릭을 직렬화한다. 같은 미완료 결제는 재사용하며 다른 진행 중인 구독 결제와 중복 생성하지 않는다.
- 서명된 webhook에서도 paid 구독 및 실제 기간·가격을 확인한 후 권한을 적용한다. 공급자 조회 실패를 30일 유료 권한으로 바꾸지 않고 500으로 재시도한다. 재전달은 기존 기록을 갱신하고 취소된 구독을 재활성화하지 않는다. 포털 플랜 변경 시 로컬 플랜도 동기화한다.
- 인기 배지, 최상단 보장, 전담 지원 등 근거·제공 구현이 확인되지 않은 혜택은 제거했다. 실제 매물 수·추천 노출 수를 표시하며 계약·문의 성사를 보장하지 않는다.

## 운영자

/admin/operations: 답변 대기·24시간 이상 대기, 정책 수집, 최근 7일 실제 행동, 활성 유료 구독 기록, 결제 완료 청구액을 확인한다. 관리자 권한을 검사한다. 모바일 메뉴는 가로 스크롤로 별도 처리해 본문이 좁아지지 않도록 개선했다.

결제 완료 청구액은 Stripe의 paid 시각이 이번 KST 월에 속하고 서비스 구독 참조가 있는 청구서만 합산한다. 다른 제품의 결제와 테스트 결제는 제외한다. 환불·수수료 차감 전이고 정산금·이익이 아니다. 조회는 최대 500개이며 남은 기록이 있으면 일부 조회라고 표시한다. 조회 실패는 0으로 바꾸지 않는다.

/admin/stats/today API에도 관리자 검사를 추가하고 서버 시간대에 관계없이 한국 날짜의 자정을 사용하도록 수정했다.

/admin/inquiries에서 기존 사전 신청과 고객 의견 조회 API를 실제 운영 화면으로 연결했다. 신청·가입·초대 기록을 구분하고 연락처를 확인할 수 있다. 메일 작성은 운영자가 클릭한 뒤 메일 프로그램에서 직접 진행하며 자동 발송하지 않는다. 사전 신청을 유료 고객·실사용자로 계산하지 않는다. 목록 조회는 10초 제한, 실패 때 이전 목록 유지, 신청 50개씩 조회·의견 최근 200개 한도를 표시한다. 이메일로 들어온 회신·별도 문의는 메일함에서 따로 확인한다.

최종 테스트·빌드·운영 배포 결과는 아래 완료 기록에 추가한다.

최초 로컬 검증은 실제 PostgreSQL의 별도 QA 스키마와 합성 계정으로 진행했다. 390×844 / 1440×1000에서 기록 다운로드, 백업 복원, 확인 전 미교체, 손상 파일 보존, 공개 안내, 집주인 결제 준비 상태·가짜 success URL, 운영자·집주인 권한 구분을 확인했다. QA 스키마의 comments.author_id 타입을 실제 합성 users 타입과 맞추고 48시간 대기 질문 1건으로 집계를 검증한다. 운영 데이터는 쓰지 않았다.

## 남은 사업 증거와 외부 설정

- 로컬 .env.local에는 Stripe 네 가지 설정이 없다. 운영 설정과 실제 결제·웹훅·포털 연결은 따로 확인해야 한다. 공급자 모킹 테스트를 실제 결제 성공으로 보고하지 않는다.
- 회사가 선택할 첫 유료 고객군·상품·응대 담당자·모집 채널에 대해 사용자에게 확인 질문을 보냈다. 기존 집주인 모델을 점검하고 무료 계약 준비의 실용성을 보완하는 작업은 계속 진행했다.
- 실제 신규 고객, 구매, 재방문, 결제 수익을 아직 입증하지 않았다. 모집 문서·기능·내려받기 횟수는 그 증거를 대신하지 않는다.
- 외부 모집 발송·게시나 결제 키 설정을 임의로 진행하지 않았다. 공식 문의 주소는 기존 개인정보처리방침에 공개된 ipjuhae.official@gmail.com을 사용한다.
