## 변경

- 첫 화면의 행동을 보증금 점검·후보 집 비교·계약 전 질문으로 정리했다. 가입 없는 점검을 주 행동으로 유지했다.
- 정책소식을 핵심 행동 바로 다음에 배치했다. 홈에는 3건을 보여주고 `/policy/news` 전체 목록으로 연결했다.
- 안내 글은 연재별 3편만 펼치고 나머지는 네이티브 details로 열도록 했다. 모든 원문 링크를 유지했다.
- 비로그인 PC 메뉴와 모바일 메뉴에 점검·정책소식·질문 게시판·전세 제도 경로를 추가했다. 로그인 경로도 제공한다.
- 주택 공급·공공주택·청약·노후주택·주거복지·전입세대·상생임대 관련 필터를 보완했다. 농지·상가·재난·일반 경제 기사 제외 회귀를 유지하고 CM용역·경마장 등 공사 행정 소음을 제외했다. 동일 원본 확인 결과 13건이 선택됐다.
- 최근 수집 시각, 최신 발표일, 한국 날짜 기준 오늘 발표 수를 구분한다. 오늘 정상 조회했지만 새 발표가 없으면 그 사실을 표시한다. 오늘 조회 여부가 미확인이거나 수집 실패면 새 발표가 없다고 단정하지 않는다.
- `/policy/news`에서 주제 선택과 제목·기관 검색, 최신 저장 결과 읽기 버튼을 제공한다. 열린 화면은 5분마다, 탭 복귀 때 갱신한다.
- 공개 `/api/policy-news`는 하나의 DB 스냅샷에서 기사와 상태를 읽는다. 공개 요청은 원본 수집기를 실행하거나 API 쿼터를 소비하지 않는다.
- 최신 일부 수집 실패는 `degraded` 상태와 HTTP 503으로 보고한다. 직전 정상 기사는 유지한다. 화면 조회 네트워크 오류·DB 장애·10초 요청 지연에도 기존 소식과 다시 시도 버튼을 유지한다.

## 검증

- 린트 통과, 기존 다른 화면의 hook/img 경고는 남아 있다. 변경 파일의 린트 오류 없음.
- 타입 검사 및 최종 프로덕션 빌드: 실행 결과를 아래 최종 기록에서 확인한다.
- 전체 테스트: 최초 1,023개 통과 / 13개 건너뜀. 장애·시간 초과 복구 테스트 2개 추가 후 최종 결과를 아래 기록에 남긴다.
- 실제 로컬 PostgreSQL의 별도 `qa_home_policy_20261011` 스키마에서 검증했다. 정책소식은 읽기 전용 원본 확인으로 가져온 실제 공개 기사이고, 안내 글 18편은 로컬 합성 픽스처다. 운영 DB에 데이터를 쓰지 않았다.
- 로컬 프로덕션 Playwright 390×844와 1440×1000에서 메뉴, 안내 펼치기, 정책소식 주제·검색·조회, 네트워크 실패 후 기사 보존, 후보 집 비교 진입, 가로 넘침 없음, JavaScript 오류 0을 확인했다.
- 모바일 소식 섹션 시작 720px / PC 546px. 모바일 전체 높이 3,923px / PC 2,403px. 기존 운영 화면과 로컬 픽스처 사이의 측정이며 실제 방문자 성과가 아니다.
- 재검증 스크립트: `QA_BASE_URL=http://127.0.0.1:3141 node scripts/qa/check-home-policy-browser.cjs`. 현재 검증에는 연재 2개·정책기사 10건 이상·청약 기사가 있는 로컬 픽스처가 필요하다.

## 남은 운영 단계

배포 승인 후 기능 브랜치를 검토·병합하고 Fly 배포 결과를 확인한다. DB 스키마 변경은 없다. 기존 수집 스케줄은 유지된다. 새 필터가 운영 저장 결과에 적용되려면 배포 후 실제 전체 수집 성공을 확인해야 한다. 배포만으로 저장 기사 13건 반영을 주장하지 않는다.

운영에서 PC·모바일 홈과 `/policy/news`, 정책소식 목록·상태 API, 실제 수집 완료와 새 필터 결과, 실패 상태 HTTP 503을 재확인한다. 실제 사용자 이용·전환 효과는 아직 측정하지 않았다. 원본에 새 발표가 없는 날에 새 기사를 만들어 표시하지 않는다.

## 사용 이유·재방문에 집중한 최종 범위

사용자는 모든 기능을 노출하기보다 지금 쓸 이유와 모일 경로를 우선하도록 지시했다. 홈에서 계약 대화·파일럿 홍보·매물 탐색 링크를 덜어냈다. 첫 행동은 가입 없는 보증금 점검이며 후보 집 저장·비교, 남은 확인 목록, 확인 항목 질문으로 이어진다. 홈의 `내 계약 준비 이어보기`는 이 브라우저에 저장한 후보 수·남은 확인 수·보관한 질문 수를 읽고 해당 화면으로 연결한다. 입력 금액·후보 이름·질문 ID를 홈에 표시하거나 서버에 보내지 않는다. 저장 데이터 손상과 다른 탭의 변경도 처리한다. 지인에게 보낼 공개 점검 링크를 홈에 추가했고 새로운 정책소식 페이지를 sitemap에 포함했다.

최종 로컬 검사: 전체 테스트 1,029개 통과 / 13개 건너뜀, 109개 파일 통과 / 3개 파일 건너뜀. 타입 검사·프로덕션 빌드·변경 파일 린트 통과. 기존 다른 화면의 lint 경고는 남아 있다.

사람이 모였다는 성과는 별도 검증한다. 첫 목표는 계약을 앞둔 실제 대상자 10명의 점검 이용·불편 수집이며 현재 이용자 수가 아니다. 기존 `docs/launch/real-user-operations.md`의 모집문과 운영 절차를 사용한다. 지정 채널 없이 외부 계정 게시·지인 발송은 하지 않았다. 관리자가 매일 질문을 확인하고 응대해야 하며 담당과 확인 시간은 아직 정해지지 않았다. 새 기능 성공과 실제 사용자 성과를 섞어 보고하지 않는다.
