# DOW-1136 — 커뮤니티 글쓰기 진입점 3개 동작 통일

작성일: 2026-09-24
담당: 입주해
관련: DOW-1135(UXDesigner 조사), DOW-730(Providers 경계)

## 결함

`components/community/community-board.tsx`의 글쓰기 진입점 3개가 서로 다른 함수를 불렀다.
**사용자가 어디서 열었느냐에 따라 글이 다른 게시판에 올라갔다.**

| 진입점 | 기존 호출 | 결과 |
| --- | --- | --- |
| 카드 안 "지금 막히는 게 무엇인가요" | `startWriting()` | `audience`를 내 역할 게시판으로 맞춤 |
| 목록 상단 "글쓰기" | `setWriting(true)` | `audience`가 초기값 `all`에 머묾 |
| 빈 상태 "첫 글 남기기" | `setWriting(true)` | 동일하게 `all`에 머묾 |

부수 결함: `startWriting()`이 `setWriting((v) => !v)` 토글이라 셋 중 하나만 동작이 달랐다.
또 대상 선택 UI 전체가 `userType &&`에 묶여 **비로그인 사용자는 어디에 올라가는지 모른 채**
올리기를 눌렀다.

## 수정 — CEO 확정 명세대로

진입점 3개를 `openWriting()` 하나로 합쳤다. 이 함수는 토글이 아니라 항상 열기이고,
닫기는 `취소` 버튼만 담당한다.

대상 게시판 기본값은 `defaultAudienceFor(tab)` 한 곳에서 정한다.

- **지금 보고 있는 탭을 따른다.** 임대인 탭을 읽다가 글쓰기를 누르면 임대인 게시판.
- **탭이 `all`일 때만** 로그인 사용자는 본인 역할 게시판(`userTypeToAudience`),
  비로그인 사용자는 `all`.

탭을 바꾸면 폼이 열려 있는 동안에도 대상이 따라간다. 단 사용자가 대상 버튼을 직접 누르면
`audiencePicked`가 서고, 그 뒤로는 탭 변경이 선택을 덮어쓰지 않는다.

대상 문구(`"○○ 게시판에 올라갑니다"`)는 **비로그인 포함 전원에게** 보인다. 선택 *버튼*은
기존대로 권한 있는 사용자에게만 보인다. 어디에 올라가는지 모른 채 올리는 상태를 없애는 게 목적.

작성 실패의 `alert()`은 `toast.error()`로 바꿨다(`sonner` — 저장소의 기존 패턴).

부수 정리: 쓰이지 않던 `useRouter()`와 `ownAudience`를 지웠다.

## 회귀 테스트

신규 `__tests__/components/community-board-write-entry.test.tsx` (jsdom, 16 cases).

**"진입점이 같은 함수를 부르는지"를 소스에서 확인하지 않는다.** 진입점 3개를 각각 실제로
눌러서 폼에 표시되는 대상 게시판 문구를 읽는다. 사용자가 실제로 보는 값이 판정 기준이어야
진입점이 또 갈라질 때 잡힌다.

커버 항목:

- 진입점 3개 × (임대인 로그인 / 비로그인) = 6건 — 대상 게시판 일치
- 기본값 규칙 3건 (탭 따라가기 / `all`+로그인 / `all`+비로그인)
- 탭 변경 추종 1건, 직접 선택 후 비덮어쓰기 1건
- 토글 아님 1건, 취소로만 닫힘 1건
- 비로그인 대상 문구 렌더 1건 (선택 버튼은 없음도 함께 확인)
- 실패 시 `alert` 미호출 + `toast.error` 호출 1건, 성공 시 폼 닫힘 + 전송 `audience` 1건
