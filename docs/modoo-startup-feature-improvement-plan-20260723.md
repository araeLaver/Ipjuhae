## 1. 요약

Rentme(입주해)는 세입자와 임대인이 계약 전 필요한 확인 항목을 동의 기반으로 정리하고, 원본 증빙 대신 최소한의 확인 상태와 설명 가능한 리포트를 제공하는 주거 신뢰 데이터 서비스로 고도화한다.

현재 MVP는 세입자 프로필, 임대인 매물 관리, 매칭, 메시지, 커뮤니티, 검증 문서, 레퍼런스, 신뢰 리포트 집계 API를 포함하고 있다. 2026-07-23 기준 TypeScript typecheck, Vitest 333개 테스트, Next.js production build가 통과했다.

2026-07-26 1차 제품 반영으로 `검증값 표준 필드`, `운영 검수 API/화면`, `공개결정 스냅샷`, `리포트 번들`, `동의 철회 후 공개 회수`, `만료 자동 회수 cron`, `이의제기 공개 회수 hook`, `외부 제출자료 점검 명령`이 코드와 migration에 추가됐다. TypeScript typecheck, Vitest 340개 테스트, 공개자료 점검, Next.js production build가 통과했다. 단, 로컬 DB role 문제로 migration 023 적용 증거는 아직 확보하지 못했으므로 운영자료에는 `코드 반영 및 검증 완료, DB 적용 대기`로 구분한다.

모두의창업 기간의 기능개선 방향은 신규 기능을 넓게 추가하는 것이 아니라, 이미 구현된 MVP를 다음 네 가지 증빙 가능한 결과로 정리하는 것이다.

| 개선축 | 핵심 목표 | 제출자료에서 보여줄 증거 |
| --- | --- | --- |
| 동의 기반 확인 리포트 | 신용평가나 계약 보장이 아닌 계약 전 확인 항목 리포트로 재정의 | 개인정보 없는 mock 리포트, 공개 범위표, 접근 로그 화면 |
| 문서/OCR 검증 워크플로우 | 원본 증빙과 파생 검증값을 분리하고 사람 검수 절차를 연결 | 가상 문서 업로드, OCR 추출값, 검토 상태, 반려/정정 흐름 |
| 공공데이터 기반 지역 설명 AI | 세입자 평가가 아니라 지역·거래·생활권 맥락 설명으로 AI 범위 제한 | 전월세 실거래가/법정동/교통/생활 인프라 기반 샘플 리포트 |
| 출원기술 구현 근거 패키지 | 특허 핵심구조를 구현 완료/부분 구현/확장 실시예로 분리 | 구현 매트릭스, 코드 경로, demo 화면, 미구현 백로그 |
| 투자심사형 운영지표 패키지 | 기술 구현, 법률 리스크 관리, 고객검증, 시장성 증거를 한 묶음으로 제시 | 빌드/테스트 결과, 인터뷰 기록, 상담 결과, 전후 개선표 |

기율 문서 전수 검토 기준으로 모두의창업 기간에 우선 반영할 P0 기능은 `검증값 표준화`, `공개결정/리포트 스냅샷`, `동의 철회·이의제기·만료 후 공개 회수`, `레퍼런스 이의제기와 재계산 연결`, `외부 제출자료 공개통제 점검`이다. 사업계획서에는 이를 기술 세부가 아니라 사용자 가치와 리스크 관리 결과로만 적되, 내부 실행계획에는 출원기술별 구현 상태와 부족한 기술 보강 항목을 명확히 남긴다.

## 2. 투자심사보고서형 구성 반영

긴트 투자심사보고서의 구조는 `투자개요 -> 기업 일반 현황 -> 재무 현황 -> 사업 타당성 분석 -> 기업가치 검토 -> 종합 의견` 순서다. 입주해는 아직 pre-seed/MVP 단계이므로 이 구조를 그대로 복제하지 않고, 아래처럼 기능개선 계획에 맞게 변환한다.

| 긴트식 심사 관점 | 입주해 자료 반영 방식 |
| --- | --- |
| 투자개요 | 해결 문제, 개선 목표, 모두의창업 기간 내 산출물, 필요한 자금 사용처 |
| 기업 일반 현황 | 현재 MVP 구현 범위, 검증된 route/API, 테스트/빌드 통과 사실 |
| 재무 현황 | 확정 매출 대신 비용 구조, 구독/리포트/B2B workflow 수익 가설, 6개월 검증 KPI |
| 사업 타당성 분석 | 주거 정보 비대칭, 개인정보 과다 제출, 임대차 신뢰 부족 문제와 초기 고객검증 |
| 기업가치 검토 | 정량 valuation보다 기술 차별성, 데이터 구조, 법률 리스크 통제, 확장 가능성 |
| 종합 의견 | P0 기능개선 완료 시 투자검토 가능성이 높아지는 조건과 남은 리스크 |

## 3. 현재 기능 기준선

현재 제품은 사업계획서에서 `구현 예정 아이디어`가 아니라 `검증 중인 MVP`로 설명할 수 있다.

| 영역 | 현재 확인된 기능 | 개선 필요점 |
| --- | --- | --- |
| 세입자 프로필 | 기본 정보, 생활 조건, 자기소개, 온보딩 | 공개 범위와 정정/철회 UX를 더 명확히 해야 함 |
| 임대인 탐색 | 세입자 검색, 매물 등록, 매칭, 메시지 | 필터가 차별/자동심사로 보이지 않도록 표시와 사용 제한 필요 |
| 확인/검증 | 재직·소득·신용 관련 확인, 문서 업로드, 레퍼런스 | 원본·OCR·검증값·리포트 공개값의 분리 증거 필요 |
| 리포트 | `/api/reports/*/aggregate`, 확인 항목 기반 요약 | 점수 중심 표현을 낮추고 목적별 공개 필드 제어 강화 |
| 운영/관리 | admin routes, launch smoke, 계정 삭제 API | 운영 DB, provider secret, storage, SMS/email/payment 실연동 확인 필요 |
| 품질 증거 | typecheck, unit test 333개, production build 통과 | 외부 제출용 화면 캡처와 개인정보 없는 demo story 필요 |

### 3.1 기술출원 반영 기준선

출원 관련 표현은 `특허 등록`이 아니라 `출원일 확보 및 정규출원 보강 중`으로 제한한다. 제품 기능은 아래 기준으로만 분류한다.

| 출원기술 축 | 현재 제품 반영 | 모두의창업 보강 방향 |
| --- | --- | --- |
| 원본자료 -> 검증값 변환 | `evidence_records`, `validation_values`, 문서 업로드/OCR route, migration 023, admin validation review API/UI | 운영 DB 적용, 실제 샘플 데이터 기반 검수 demo |
| 임차인·임대인·주택 3분리 | tenant/landlord/property aggregate report 골격 | 임대인·주택 리포트의 검증값 key set과 mock report 강화 |
| 동의 기반 선택 공개 | `consents`, `access_logs`, `consent-access`, `disclosure_decisions`, `report_bundles`, trust disclosure cron, reference dispute revocation hook | 운영 DB 적용, 제한 열람 UX와 사용자 알림 UX 연결 |
| 정정·이의제기 후속 처리 | 레퍼런스 이의제기와 점수 재계산 일부, 동의 철회/만료/이의제기 시 리포트 번들 회수 | 검증값 정정, 영향 범위 계산, 사용자 알림 UX 연결 |
| 거래조건 참고값 | `trade_condition_hints` CRUD | 자동 확정이 아닌 추가서류·안전조치·협의 참고값 v1로 제한 구현 |

이 기준은 모두의창업 지원금·AI 솔루션 사용 내역을 기술력 증빙으로 연결하기 위한 내부 기준이다. 외부 제출자료에는 세부 산식, 임계값, 내부 상태명, API/DB 세부를 그대로 복사하지 않는다.

2026-07-26 현재 외부 제출자료 공개통제는 `npm run docs:public-check`로 1차 점검할 수 있다. 이 명령은 기능개선 계획서와 기술출원 반영 실행계획의 위험 표현을 확인하며, 제출 직전에는 실제 제출본 파일명을 추가해서 다시 실행한다.

## 4. 기능개선 로드맵

### P0. 확인 항목 리포트 및 동의 기반 제한 열람

목표: `신뢰점수` 중심 표현을 줄이고, 세입자가 동의한 범위의 확인 상태만 임대인에게 보여주는 리포트 구조로 고도화한다.

구현/정리 항목:

- `신뢰점수`, `Trust Score`, `검증된 세입자` 표현을 외부자료에서는 `확인 항목 리포트`, `신뢰 프로필 요약`, `임대 적합 참고 지표`로 전환한다.
- 리포트 필드를 `본인 열람`, `특정 임대인 제한 열람`, `내부 운영 검토`로 나눈다.
- 열람자, 목적, 허용 필드, 연락처 공개 여부, 유효기간, 철회 상태를 표준 동의 단위로 정의한다.
- 임대인 화면에는 원본 증빙, 상세 산식, 부정 레퍼런스 원문, 전체 점수 배점을 노출하지 않는다.
- 세입자에게 정정 요청, 이의제기, 재검토 요청, 공유 철회 흐름을 제공한다.

산출물:

- 개인정보 없는 세입자 리포트 mock 1장
- 제공 동의 화면 mock 1장
- 임대인 제한 열람 화면 mock 1장
- 철회/접근내역 화면 mock 1장
- 개인정보처리방침/이용약관 수정 필요 항목표

심사 대응 포인트:

> 입주해는 임차인을 자동 평가하거나 계약 가능성을 보장하는 서비스가 아니라, 사용자가 직접 동의한 확인 항목을 목적과 기간에 따라 제한 열람하도록 돕는 계약 전 정보 정리 도구입니다.

### P0. 문서/OCR 검증 워크플로우

목표: 창업활동자금 및 AI 솔루션 활용 결과를 제품 기능 개선으로 연결한다. OCR은 자동 판정이 아니라 원본 증빙에서 확인 후보값을 추출하고 사람 검수로 확정하는 보조 기능으로 제한한다.

구현/정리 항목:

- 문서 업로드 후 `원본 파일`, `OCR 추출값`, `검토 상태`, `외부 공개용 검증값`을 분리한다.
- OCR 결과는 `자동 승인`이 아니라 `검토 필요`, `확인 완료`, `반려`, `정정 요청` 상태로 관리한다.
- 원본 파일은 임대인에게 기본 공개하지 않고, 공개 가능한 파생값만 리포트에 반영한다.
- 외부 AI/API 사용 시 학습 이용 금지, 위탁/국외이전, 보유기간, 삭제 기준을 정책에 반영한다.
- 개인정보 없는 가상 문서로 demo 영상을 만든다.

산출물:

- 가상 문서 업로드 화면
- OCR 추출/검토 상태 화면
- 검토자 승인/반려 사유 예시
- 원본/추출값/검증값/공개값 분리표

심사 대응 포인트:

> AI는 임차인의 신용이나 계약 가능성을 판단하지 않고, 사람이 확인할 증빙 항목을 빠르게 구조화하는 생산성 도구로 사용합니다.

### P1. 공공데이터 기반 지역·거래·생활권 설명 AI

목표: AI 활용 범위를 개인 평가가 아니라 공개 데이터 기반 설명으로 옮겨 규제 리스크를 낮추고, 투자자료의 시장성·확장성을 보강한다.

구현/정리 항목:

- 전월세 실거래가, 법정동 코드, 부동산 통계, 공공임대주택, 교통, 보육/생활 인프라 데이터를 후보 데이터셋으로 정리한다.
- 매물/지역 리포트에서 `공공데이터 기반 설명`과 `사용자 동의 기반 요약`을 라벨로 분리한다.
- AI 출력은 “이 지역의 전월세 거래 범위”, “생활 인프라”, “사용자가 직접 확인해야 할 항목” 중심으로 제한한다.
- 신용평가, 임차인 자동 합격/탈락, 법률 자문, 보증 가능성 판단 문구는 제외한다.
- 샘플 매물 3개와 synthetic profile 3개로 개인정보 없는 demo를 구성한다.

산출물:

- 공공데이터 활용 목록표
- 지역 리포트 sample 3건
- AI 설명문 생성 전후 비교표
- 데이터 출처/갱신주기/품질 한계표

심사 대응 포인트:

> 입주해의 AI는 사람과 계약을 대신 판단하는 엔진이 아니라, 공개 주거 데이터를 이해하기 쉽게 설명하고 확인 질문을 제안하는 도구입니다.

### P1. 임대인 검색 및 매칭 UX 안전화

목표: 임대인이 조건에 맞는 세입자를 찾는 핵심 UX를 고도화하되, 차별적 선별이나 자동심사로 해석될 수 있는 기능은 제한한다.

구현/정리 항목:

- 세입자 카드에는 이름 마스킹, 확인 상태 배지, 공개 허용 항목, 리포트 만료일을 우선 표시한다.
- 숫자 점수 필터는 법률 검토 전 외부 UI에서 제외하고, 확인 항목/레퍼런스 보유 여부/거주 조건 중심으로 검색한다.
- 검색 결과에는 `추천 사유`가 아니라 `일치한 조건`과 `추가 확인 필요 항목`을 표시한다.
- 집주인 열람, 메시지 시작, 연락처 요청은 동의와 목적 확인 후 진행한다.
- 필터 사용과 리포트 열람 이력을 access log에 기록한다.

산출물:

- 임대인 검색 필터 개선 화면
- 세입자 카드 개선 전후 비교
- 차별/자동심사 오인 방지 문구
- 열람 로그 샘플

심사 대응 포인트:

> 임대인 검색은 사용자가 공개한 조건을 바탕으로 대화를 시작하기 위한 탐색 도구이며, 임차인 자격 판단이나 계약 체결 보장을 제공하지 않습니다.

### P1. 법률·개인정보 검토 반영 패키지

목표: 투자자와 지원사업 심사자가 우려할 법률 리스크를 기능개선 항목으로 흡수한다.

구현/정리 항목:

- K-Startup 원스톱 또는 마이데이터 전문가 자문을 통해 동의, 제3자 제공, 신용정보 오인, 중개행위, IP 쟁점을 검토한다.
- 상담 전에는 실제 개인정보, 원본 증빙, 운영 DB, secret, 전체 산식, 세부 배점을 제출하지 않는다.
- 상담 결과를 개인정보처리방침, 이용약관, 리포트 고지문, 집주인 화면 고지, 이의제기 정책에 반영한다.
- `신용 인증`은 `신용 관련 확인 항목`, `검증된 세입자`는 `확인 항목이 정리된 프로필`로 완화한다.

산출물:

- 전문가 자문 질문 5개
- 정책 수정 전후 비교표
- 위험 표현 대체 문구표
- 투자자료 법률 리스크 슬라이드

심사 대응 포인트:

> 초기 서비스의 핵심 리스크를 출시 후 대응이 아니라 출시 전 기능 설계와 정책 문구에 반영합니다.

### P2. 투자심사형 운영지표 대시보드

목표: 투자유치 자료에서 “좋은 아이디어”가 아니라 “개선 속도와 검증 능력”을 보여준다.

구현/정리 항목:

- 테스트/빌드/배포 준비 상태를 일일 품질 증거로 축적한다.
- 세입자 인터뷰, 임대인 인터뷰, 전문가 상담, mock 리포트 반응을 하나의 검증 로그로 묶는다.
- 퍼널 지표를 `프로필 생성 -> 확인 항목 제출 -> 리포트 생성 -> 제한 공유 -> 메시지 시작`으로 정의한다.
- 초기 수익화는 데이터 판매가 아니라 본인 리포트 관리, 동의 기반 공유, 임대관리자 workflow 구독으로 둔다.

산출물:

- 기능개선 전후표
- 고객검증 인터뷰 요약
- 6개월 KPI 표
- IR deck용 traction slide

심사 대응 포인트:

> 입주해는 매출이 없는 초기 단계에서도 제품 완성도, 법률 리스크 관리, 고객검증 속도, 데이터 구조의 방어력을 추적 가능한 지표로 제시합니다.

## 8. 사업계획서에 넣을 기능개선 문안

아래 문단은 사업계획서의 `기능개선사항 및 고도화 계획` 섹션에 바로 사용할 수 있다.

```text
입주해는 현재 구현된 세입자 프로필, 매칭, 메시지, 검증 문서, 레퍼런스, 리포트 API를 기반으로 모두의창업 기간 동안 동의 기반 확인 리포트 서비스로 고도화할 계획입니다. 기존의 점수 중심 표현은 신용평가나 계약 가능성 보장으로 오인될 수 있으므로, 외부 화면과 제출자료에서는 `확인 항목 리포트`, `신뢰 프로필 요약`, `임대 적합 참고 지표`로 표현을 완화합니다.

첫째, 세입자가 특정 임대인에게 어떤 항목을 어떤 목적과 기간으로 공개할지 선택하는 제한 열람 기능을 강화합니다. 열람자, 목적, 허용 필드, 연락처 공개 여부, 유효기간, 철회 상태를 기준으로 접근을 제어하고, 누가 언제 어떤 목적으로 열람했는지 기록합니다.

둘째, 재직·소득·신용 관련 확인 문서와 이전 임대인 레퍼런스는 원본 자료를 임대인에게 직접 제공하지 않고, OCR 추출값과 사람 검수를 거쳐 확인 여부·검토 상태·갱신 시점 중심의 파생값으로 리포트에 반영합니다. 이를 통해 개인정보 과다 제출 부담을 줄이고, 잘못된 자동판정 위험을 낮춥니다.

셋째, AI 기능은 임차인 평가가 아니라 공개 공공데이터 기반 지역·거래·생활권 설명에 우선 적용합니다. 전월세 실거래가, 법정동 코드, 교통, 공공임대, 생활 인프라 데이터를 활용해 사용자가 직접 확인해야 할 항목을 설명하고, 법률 자문·신용평가·보증 가능성 판단은 제공하지 않습니다.

넷째, 기능개선 결과는 mock 리포트, 동의 화면, OCR 검토 화면, 접근 로그, 고객 인터뷰, 법률/개인정보 자문 반영표, 테스트/빌드 결과로 증빙합니다. 이를 통해 입주해는 초기 단계에서도 기술 구현 가능성, 규제 리스크 관리, 고객검증 속도, 투자심사 대응력을 함께 보여줄 수 있습니다.
```

## 9. 투자자료에 넣을 기능개선 문안

```text
입주해의 제품 차별성은 단순 AI 점수 모델이 아니라, 계약 전 확인 항목을 동의 기반으로 수집·검증·제한 공유하는 데이터 workflow에 있습니다. 사용자는 본인의 임대 관련 확인 항목을 직접 통제하고, 임대인은 원본 서류가 아닌 최소한의 확인 상태와 추가 확인 필요 항목만 열람합니다.

향후 6개월간 입주해는 1) 동의 기반 확인 리포트, 2) 문서/OCR 검증 workflow, 3) 공공데이터 기반 지역 설명 AI, 4) 임대인 검색 UX 안전화, 5) 운영지표 대시보드를 순차 고도화합니다. 이 로드맵은 개인정보·신용정보·중개행위 오인 리스크를 낮추면서도, 임대차 전 단계의 정보 비대칭을 줄이는 시장성을 검증하기 위한 실행 계획입니다.
```
