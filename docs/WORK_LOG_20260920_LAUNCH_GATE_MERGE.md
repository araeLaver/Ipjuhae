# 워크로그 2026-09-20 (6) — launch 게이트 11건을 1건으로, 모집 문안 요건 정정

## 1. launch blocked 중복 정리 (DOW-1077)

기술 계열 blocked 16건 중 11건이 **같은 걸 다른 날 다시 묻는 중복**이었다.
전부 "운영 secret/provider를 어떻게 주입할지 + launch smoke 증적을 어디 남길지"다.

중복 10건을 닫고 단일 게이트 DOW-912로 합쳤다.

| 닫은 것 | DOW-364, 618, 619, 620, 782, 783, 787, 788, 838, 898 |
| --- | --- |
| 단일 게이트 | DOW-912 (blocked 유지, priority critical) |
| 못 닫은 것 | DOW-786 — 소유권 미인계(checkout 409). 소유자 조치 요청 댓글만 남김 |
| 손대지 않은 것 | DOW-447, 637, 718, 841 — 별도 보드 결정·물리 환경 사유 |

각 이슈에 **"done은 검증 통과가 아니라 추적 창구 통합"**이라고 명시했다.
이걸 안 적어두면 다음에 누가 열어보고 "런치 검증 끝난 거네"로 읽는다.

DOW-912 본문에 보드 질문 4개를 넣었다. **값은 묻지 않는다.**
① production target을 Fly.io `ipjuhae-production`으로 고정할지
② secret 주입 경로와 key 존재 증적 제공 책임자
③ SMS/Email/Storage/Verification provider 계약 주체
④ `_migrations` manifest 적용 여부와 `launch:check`/`launch:verify` 증적의 read-only 경로

### checkout 409는 또 내 좀비 실행이었다

10건 전부 첫 checkout이 409였다. `assigneeAgentId`는 나인데 `executionRunId`가
이전 큐 실행에 물려 있었다. `release` → `checkout` 순서로 전부 풀렸다.
남의 락이 아니라 내 잔여 락이면 이 순서가 정답이다.

## 2. 모집 문안 구글 요건 정정 (DOW-1078)

`docs/TESTER_RECRUIT.md`가 외부에 그대로 나갈 문안인데 요건을 틀리게 적고 있었다.

**틀렸던 것.** "한 명이라도 지우면 처음부터 다시 시작합니다."
**맞는 것.** 신청 시점 기준 직전 14일 연속 옵트인 테스터가 12명 이상이면 된다.
한 명이 빠지면 그 자리를 새로 채운 사람의 14일만 다시 시작한다.
나머지 인원의 시계까지 초기화된다는 근거는 없다.

틀린 요건을 공지하면 참여자에게 없는 의무를 지우고, 나중에 사실이 드러나면
공지 전체의 신뢰가 같이 깎인다.

같이 고친 것:

- A 문안(개발자 상호 테스트)의 "오늘 안에 설치하고 14일 유지합니다" 무제한 확약을
  "수용 가능 인원을 확인한 뒤 개별 확정"으로 교체. 한도 확인 전 확약 금지라는
  CEO 결정과 `TESTER_RECRUIT_PLAN.md` 74행 기준에 맞췄다.
- B·C 문안의 "깔고 있어야", "지우지만 말아줘"를 참여(옵트인) 유지 기준으로 정정.
- 유료 대행 문단의 "거절되면 14일을 통째로 날린다"를 실제 재신청 절차로 교체.
- 구글 공식 안내 URL과 확인일을 문서 HTML 주석으로 첨부.

`docs/TESTER_RECRUIT_PLAN.md`는 이미 맞게 쓰여 있어서 손대지 않았다.
문안과 계획이 이제 같은 기준을 말한다.

커밋 `54c869fa`, `origin/main` push 완료.
