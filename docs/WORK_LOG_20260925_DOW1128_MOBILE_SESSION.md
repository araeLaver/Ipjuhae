## 무엇이 고쳐졌나

### 1. 세션이 끊기면 로그인 화면으로 돌아간다

종전에는 401을 받으면 `apiClient`가 토큰만 지웠다. `AuthContext`의 `user`는
그대로라 `AppNavigator`는 인증 스택에 머물렀다. 결과적으로 **모든 화면이 실패만
하고 로그인으로 갈 길이 없었다.** 앱 강제 종료가 유일한 탈출구였다.

`apiClient.onUnauthorized()` 구독을 두고 `AuthContext`가 이를 받아 `user`를
비운다. 비인증 스택으로 전환되면서 `SessionExpiredBanner`가 안내를 남긴다.

### 2. 서버가 준 한국어 문구가 사용자에게 도달한다

이 저장소의 API 라우트는 압도적으로 `{ error }` 형태로 응답하는데, 앱은
`{ message }`만 읽었다. 그래서 `집주인 인증이 필요한 기능입니다` 같은 문구가
전부 버려지고 `HTTP 403`이 그대로 노출됐다. 문구가 없을 때를 대비해 상태코드별
한국어 폴백도 뒀다.

### 3. 서류 업로드도 같은 401 처리를 탄다

`uploadFile()`만 401 처리가 빠져 있었다. `VerificationScreen`에서 만료 토큰으로
서류를 올리면 실패하면서도 **만료된 토큰이 기기에 그대로 남았다.**

### 4. 앱 화면 6곳이 조회 실패와 빈 상태를 구분한다

웹에서 닫은 문제(DOW-1166)가 앱에는 그대로 있었다. `catch`에서 `console.log`만
하고 빈 배열·0을 그리면, 서버가 죽어도 사용자에게는 "아직 아무것도 없음"으로
보인다. Home·Profile·Verification·Matches·Messages·ChatRoom에 실패 배너와
"다시 시도"를 넣었다.

## 검증에서 드러난 것 — 부분 실행은 통과했지만 전체는 깨졌다

첫 커밋(`da137f1b`)을 만들 때 대상 테스트 파일 2개만 돌렸고 21건 전부 통과했다.
그 상태로 커밋했다. 이후 전체 스위트를 돌리자 **다른 파일에서 4건이 깨졌다.**

원인은 401 판정 기준이었다. "토큰을 들고 보낸 401만 세션 만료"로 갈랐더니,
**토큰이 이미 비워진 뒤에 날아간 요청의 401이 복구 경로를 타지 못했다.**
`notificationService`의 push token 정리 `DELETE`가 정확히 그 구멍에 빠져
DOW-1117 회귀 테스트 3건이 무너졌다.

`d0eaaffe`에서 기준을 `AUTH_ENTRY_POINTS`(`/auth/login`·`signup`·`register`·
`logout`)로 바꿨다. 가르는 건 토큰 유무가 아니라 **요청의 성격**이다. 로그인·가입은
401이 정상 응답이라 서버 문구를 보여주고, 나머지 401은 전부 세션 만료다.

곁가지로 `AuthContext.logout()`이 서버 로그아웃 실패를 그대로 던져 미처리
거부(unhandled rejection)가 되던 것도 고쳤다. 오프라인이나 세션 사망 상태에서
로그아웃하면 RN 레드박스가 떴을 경로다.

또 하나: 첫 커밋 메시지에 "루트 tsc 통과"라고 썼는데 **틀린 확인이었다.**
실제로는 테스트 파일에서 `TS18046` 7건이 나고 있었다. 타입체크 실패는 CI를
멈춰 push 스택 전체를 막으므로, 확인 명령의 출력을 직접 읽지 않고 종료 코드만
믿으면 안 된다.
