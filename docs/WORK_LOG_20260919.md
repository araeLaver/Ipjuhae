사전신청 대기열을 버렸다. 신청 1명, UTM 유입 0으로 표본이 만들어지지 않았다.

## 막혀 있던 것들

**커뮤니티가 로그인 벽 뒤에 있었다.** 목록·상세 API가 둘 다 401이었다.
유입 장치로 쓰려면 검색이나 SNS에서 들어온 사람이 바로 읽을 수 있어야 하는데
로그인 화면을 만나고 돌아갔을 것이다.

**중개사 계정을 만들 수 없었다.** `users_user_type_check`가 tenant/landlord/admin만
받는데 제품 코드 18개 파일은 이미 `broker`를 전제로 동작하고 있었다. 계정만 못 만드는
상태였다. `waitlist`와 `feature_requests`는 또 `agent`를 쓰고 있어서 세 테이블의 값이
서로 달랐다. **`broker`로 통일했다** — `agent`는 임대인의 대리인과 혼동된다.

**앱에 커뮤니티가 아예 없었다.** 화면 14개 중 커뮤니티가 없었고, 로그인해야 탭에
들어갈 수 있었다. 웹만 열어놓고 앱은 막아두면 앞뒤가 맞지 않는다.

## 운영자 글은 실제 콘텐츠로

빈 게시판은 다시 오지 않고, 가짜 글은 더 나쁘다. 이미 써둔 원고를 옮겼다.
`scripts/seed-community-guides.mjs`가 `marketing/sns/carousels.mjs`를 읽어
**등기부 뜯어보기 12편 + 임대인 노트 6편**을 운영자 글로 만든다. 제목이 같으면
본문만 갱신하므로 여러 번 돌려도 중복이 안 생긴다.

## 기호를 걷어냈다

글에 줄표(—)와 네모(■)가 박혀 있어 사람이 쓴 글로 읽히지 않았다.
원고 파일(`carousels.mjs`)에서부터 지웠다. 소제목은 한 줄로, 순서 있는 것만 숫자.
`갑구 — 소유자` 같은 표기도 `갑구에 적힌 소유자`로 바꿨다.

## 안드로이드 출시를 막던 세 가지

**1. 신고 수단이 없었다.** 가입 없이 누구나 쓰는 익명 게시판인데 신고가 없으면
Apple 심사지침 1.2와 Play의 사용자 제작 콘텐츠 정책에 걸린다. 반려 사유다.
신고 3건이 쌓이면 운영자 확인 전에 먼저 가리도록 했다 — 잘못 가려진 글은 되돌릴 수
있지만 노출된 피해는 되돌릴 수 없다.

**2. 개인정보 처리방침이 현재 상태와 달랐다.** 커뮤니티 글의 공개 범위, IP 해시,
신고와 비공개 처리 절차를 넣었다.

**3. 스토어 자료가 옛 제품 것이었다.** 앱이 매물 매칭에서 커뮤니티로 바뀌었는데
문안은 "역방향 임대 매칭"이었다. 설명과 앱이 다르면 반려된다. 전부 다시 썼고
스크린샷도 파란 테마 시절 것을 버리고 새로 찍었다.

## 배포 경로 문제

GitHub Actions의 Fly 배포가 원격 빌더 오류(`rpc Unavailable`)로 연속 실패했다.
코드 문제가 아니라 Fly 인프라 쪽 일시 장애다. `flyctl deploy --remote-only`로
직접 올려서 해결했다. 반복되면 워크플로에 재시도를 넣는 게 좋겠다.
