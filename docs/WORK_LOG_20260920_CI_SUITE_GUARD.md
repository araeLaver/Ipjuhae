# 워크로그 2026-09-20 — CI 테스트 건강도 가드 (DOW-1070)

## 배경

같은 날 품질 점검에서 테스트 스위트 11개가 **로드 단계에서 죽어 있는데도** 오래 방치돼 있었다는 사실을 발견했다(커밋 `e44f309a`). 문제는 "실패했다"가 아니라 **"실패가 정상으로 굳었다"**는 점이었다. 실행 테스트 수가 449 → 330으로 줄었는데 CI도 사람도 아무 말을 하지 않았다.

기존 CI는 `npm run test:run`(= `vitest run`)만 돌렸다. vitest는 스위트가 로드에 실패해도 그 파일을 "실패한 파일 1개"로만 세고, **그 안에 있었어야 할 테스트가 몇 개 사라졌는지는 아무 데도 말해주지 않는다.** 그래서 사라진 119개가 조용히 묻혔다.

## 넣은 가드 2개

`scripts/check-test-suite-health.mjs`를 추가하고, CI의 Unit Tests 잡이 `npm run test:ci`(= 이 스크립트)를 돌게 했다. 스크립트가 vitest를 한 번만 실행하면서 리포터를 두 개(`default` + `json`) 붙여, 사람이 읽을 로그와 기계가 읽을 리포트를 동시에 얻는다.

### 1. 죽은 스위트 탐지

JSON 리포트에서 `status === 'failed'`이면서 `assertionResults.length === 0`인 파일을 따로 집계한다. **테스트가 단 하나도 실행되지 못한 파일** = 로드 단계에서 죽은 스위트다.

이 판별식이 중요한 이유는 두 부류를 깔끔하게 갈라주기 때문이다. 사고를 재현해 보면(`--environment=jsdom`) 실패 13개 중 11개가 죽은 스위트, 2개는 assertion이 있는 진짜 테스트 실패로 정확히 분리된다. 죽은 11개는 메시지 첫 줄이 전부 `No such built-in module: node:` — `e44f309a`에서 고친 그 증상 그대로였다.

죽은 스위트가 잡히면 파일명과 실패 메시지 첫 줄을 같이 찍는다. GitHub Actions에서는 `::error` 애노테이션과 job summary로도 올라간다.

### 2. 테스트 수 하한

`numTotalTests`가 기준치 449의 98%(= 441) 아래로 떨어지면 실패시킨다. 사고 시에는 340까지 떨어졌으니 확실히 걸린다.

기준치를 **초과**하는 것은 실패로 치지 않는다. 테스트가 늘어나는 건 막을 이유가 없다.

### 두 가드가 서로를 메우는 지점

이번 검증에서 직접 확인한 건데, 일부러 만든 빈 스위트 하나를 깨뜨렸을 때 **테스트 수는 449 그대로였다.** 죽은 파일에 원래 테스트가 없었으니 총합이 안 줄어든 것이다. 하한만 있었으면 이걸 놓쳤고, 죽은 스위트 탐지가 잡았다. 반대로 테스트 파일이 통째로 사라지면(로드 실패가 아니라 삭제) 죽은 스위트는 0인데 수가 줄어 하한이 잡는다. 둘 다 있어야 한다.

## 검증

로컬에서 완료 기준 두 가지를 모두 실측했다.

| 상황 | 종료 코드 | 실측 출력 |
| --- | --- | --- |
| 정상 | 0 | `실측 테스트 449개 / 파일 47개 / 죽은 스위트 0개 (하한 441)` |
| 스위트 1개를 일부러 깨뜨림 | 1 | `죽은 스위트 1개: 로드 단계 실패로 테스트를 실행하지 못했습니다.` + 파일명 |

깨뜨리는 데 쓴 파일(`__tests__/ci-suite-health-probe.test.ts`, 존재하지 않는 모듈을 import하는 한 줄)은 검증 후 삭제했다. 재현하고 싶으면 아무 이름으로 같은 한 줄짜리 파일을 만들면 된다.

## 기준치 갱신 방법

스크립트 상단 주석에 적어뒀고, `ci.yml`에서도 그 주석을 가리킨다. 요약하면:

1. 전체 실행이 정상인지(죽은 스위트 0개) 먼저 확인한다
2. 실측 테스트 수를 `BASELINE_TESTS`에 옮겨 적는다
3. 왜 바뀌었는지 커밋 메시지에 한 줄 남긴다

**기준치를 낮출 때가 위험하다.** 줄어든 이유를 설명할 수 있어야 한다. 설명이 안 되면 그건 기준치를 낮출 일이 아니라 고쳐야 할 회귀다. 이번 사고가 정확히 그 모양이었다.

## 구현 중 고친 것

- **`process.exit()` 대신 `process.exitCode`**: `catch` 안에서 `process.exit()`를 부르면 프로세스가 동기적으로 끝나 `finally`의 정리 코드가 돌지 않는다. `exitCode`를 세팅하고 자연 종료시킨다.
- **리포트를 작업 트리에 쓰지 않음**: `mkdtempSync`로 임시 디렉터리를 만들어 거기에 JSON을 쓰고 `finally`에서 지운다. 저장소에 `test-report.json`이 남아 실수로 커밋될 경로 자체를 없앴다(그래서 `.gitignore` 추가도 불필요해졌다).
- **가드 진단을 vitest 종료 코드보다 먼저 출력**: 로그 맨 아래에서 "왜 실패했는지"가 먼저 보이게.

## 남은 것

- CI 실환경(GitHub Actions)에서의 회귀 검증은 QA가 진행한다. 로컬에서는 애노테이션/job summary 경로를 실제로 태우지 못했다.
- 관련: 에이전트 실행 셸의 `NODE_ENV=production` 유출 건(DOW-1072)은 별건으로 대기 중.
