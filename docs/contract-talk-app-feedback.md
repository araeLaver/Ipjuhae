# 계약 전 대화 목록 · 앱 · 피드백

`/contract-talk/requests`와 Android 앱의 홈·설정에서 보낸/받은 최근 100개 요청을 확인한다. 첫 응답 전 지정 이메일의 임대인은 기존 shared 링크로, 응답 후 양측은 private 상세로 연결한다. 기존 서버의 역할·만료·version 검증을 재사용하며 관리자에게 참가자 접근 권한을 부여하지 않는다. 목록에는 답변·이메일·계정 ID를 노출하지 않는다.

Expo 네이티브 화면은 기존 apiClient와 인증 세션을 사용한다. Origin 없는 변경 요청은 Bearer 헤더와 기존 서버 인증을 모두 통과해야 한다. Cookie만 있고 Origin 없는 요청, 명시적 다른 Origin은 계속 거절한다. 공유는 사용자가 OS 공유 창에서 직접 수행한다. 자동 이메일/푸시 발송은 추가하지 않는다. 401은 기존 세션 만료 처리로 로그인 진입을 제공하며 재로그인 후 홈/설정에서 목록을 다시 연다. 자유 입력 초안은 계정 변경 시 영속화하지 않는다.

기존 `/api/feature-requests`를 사용한다. 신규 화면은 자발적으로 적은 의견과 source만 전송하고 연락처 입력·대화 ID·원문·계정 정보를 자동 첨부하지 않는다. 사용자 입력 자체에는 개인정보를 적지 않도록 안내한다. 접수는 특정 출시일이나 기능 구현을 약속하지 않는다.

성공한 상태 변경과 같은 트랜잭션에서 `analytics_events`에 생성/응답/일정 합의/양측 확인 완료/취소를 기록한다. properties는 `{surface: 'web'|'app'}`만, user_id/session_id는 NULL이다. 답변 수정과 재합의 등 실제 전이도 동작 횟수에 포함하므로 고유 사용자 수·전환율로 해석하지 않는다. 동일 생성 key 재시도·같은 응답 재저장·이미 합의된 일정 재저장은 추가 집계하지 않는다. 클라이언트가 해당 서버 이벤트 이름을 직접 제출하면 거절한다. 상세 page_view 경로도 `/contract-talk`으로 정규화해 링크 토큰/ID를 남기지 않는다. 운영 관리자 통계 화면에는 최근 30일 날짜·이벤트·surface의 합계만 표시한다.

기존 analytics_events와 feature_requests 테이블을 사용한다. source/event_name은 자유 문자열 스키마로 신규 마이그레이션이나 기존 데이터 변환이 없다. 앱 테스트 빌드는 EAS preview APK/internal, 기존 자격 증명 고정으로 생성하며 스토어 제출은 하지 않는다. FCM 파일이 없는 테스트 빌드는 푸시 발급을 보장하지 않는다.
