# NIA 공공데이터 활용기업 AI 연계 성장지원 신청 적합성 검토

작성일: 2026-07-26  
대상 공고: `2026년 공공데이터 활용기업 AI 연계 맞춤형 성장 지원사업`

## 결론

판정: **조건부 Go**

Rentme는 현재 공공데이터를 제품에 연동하지 않았더라도 `활용 예정 기업`으로 신청할 수 있다. 저장소에는 AI 기반 매칭, OpenAI embedding 유사도, 문서 OCR, 설명문 생성 기능이 구현되어 있어 AI 활용 근거도 있다. 따라서 자격과 사업목적 적합성은 높다.

다만 이 사업은 개발비를 직접 지급하는 사업이 아니라 2026년 9~11월 맞춤형 컨설팅을 제공하는 사업이다. 신청 목적은 `전월세·법정동·교통 공공데이터를 결합한 주거 의사결정 설명 서비스`의 데이터 구조 및 AI 적용 고도화로 한정하는 것이 적절하다. 신청 주체와 필수 증빙을 확인한 뒤 제출한다.

## Rentme 자격 및 제품 근거

### 자격

- 공고는 기업뿐 아니라 예비창업자도 허용한다.
- 이미 공공데이터를 운영 중일 필요가 없고 `활용 예정`도 허용한다.
- 지역 제한, 업력 상한, 필수 매출, 필수 고용 인원은 원본 공고에서 확인되지 않았다.
- 신청 주체가 예비창업자인 경우 작성 가능한 기업 항목만 작성하고 사업자등록증은 제출하지 않아도 된다.

### 현재 AI 구현 근거

- `lib/ai-matching.ts`: 규칙 기반 점수에 지역·생활조건 점수와 선택적 OpenAI embedding 의미 유사도를 결합한다.
- `lib/ocr-pipeline.ts`, `lib/ai-omakase.ts`: 제출 문서 이미지의 OCR 및 텍스트 추출 흐름이 있다.
- `lib/openai.ts`: 자기소개 등 설명문 생성 기능과 API 미설정 시 fallback이 있다.
- `lib/trust-score.ts`, `lib/report-aggregate.ts`: 사용자 동의 데이터에서 확인 항목을 구조화하고 리포트 신호를 산출한다.

신청서에는 현재 구현과 향후 계획을 구분한다. 아직 연동하지 않은 공공데이터를 `현재 활용 중`으로 쓰지 않는다.

## 권장 공공데이터 연결 구조

| 우선순위 | 공공데이터 | 제품 연결 | 활용 방식 |
| --- | --- | --- | --- |
| 1 | 국토교통부 아파트·연립다세대 전월세 실거래가 | 매물 주변 거래 범위와 시계열 맥락 | OpenAPI |
| 2 | 행정안전부 법정동코드 | 주소 정규화와 데이터셋 간 join key | OpenAPI |
| 3 | 국토교통부 TAGO 버스정류소, 국가철도공단 역사정보 | 통근·교통 접근성 설명 | OpenAPI·파일 |
| 4 | 한국부동산원 부동산통계 | 지역 주택시장 변화 설명 | OpenAPI |
| 5 | 마이홈포털 공공임대주택 단지정보 | 주변 주거복지 공급 정보 | OpenAPI |
| 6 | 어린이집 표준데이터 | 가족 사용자 생활 인프라 설명 | 표준데이터 |

1차 신청서에는 전월세 실거래가, 법정동코드, 교통정보 3개만 전면에 둔다. 데이터셋을 과도하게 나열하기보다 `주소 정규화 → 지역별 거래·교통 feature 생성 → AI 설명문 생성 → 출처·기준시점 표시`의 흐름을 구체적으로 제시한다.

## 권장 신청 포지셔닝

서비스명 초안: **Rentme 공공데이터 기반 주거 의사결정 설명 서비스**

문제정의 초안:

> 임차인이 매물을 검토할 때 가격, 교통, 지역 생활권 정보가 여러 공공기관에 분산되어 있어 객관적인 비교가 어렵다. Rentme는 전월세 실거래가, 법정동코드, 대중교통 공공데이터를 매물 주소 기준으로 구조화하고, AI가 출처와 기준시점을 포함한 쉬운 설명으로 변환해 사용자가 계약 전 확인할 지역 맥락을 빠르게 이해하도록 돕는다.

데이터 활용 구조:

1. 법정동코드로 매물 주소를 표준화한다.
2. 전월세 실거래와 교통 데이터를 법정동·좌표·기준시점으로 결합한다.
3. 결측치, 중복, 갱신주기, 이상값을 점검해 설명용 feature를 만든다.
4. AI는 구조화된 공공데이터와 비식별 매물 정보만 입력받아 비교 설명을 생성한다.
5. 화면에 데이터 출처, 기준시점, 원문 확인 링크와 `자동 심사·법률 판단이 아님`을 표시한다.

차별점:

- 단순 매물 나열이 아니라 공공데이터의 출처·시점·근거를 보존한 설명을 제공한다.
- 사용자 동의 데이터와 공공데이터를 분리하고, AI prompt에는 주민등록번호, 연락처, 원본 증빙, 상세주소를 넣지 않는다.
- 자동 합격·탈락이나 신용평가가 아니라 사용자의 정보 이해와 추가 확인을 지원한다.

## 희망 프로그램 선택

우선 선택:

1. `AI-Ready 구축 / 공공데이터 수집 및 정제`
2. `AI-Ready 구축 / 공공데이터 구조화 및 라벨링`
3. `AI 서비스 고도화 / (기존)사업 모델 및 서비스 고도화`
4. `창업 지원 / 공공데이터·AI 연계 서비스 기획`

보조 선택:

- `AI 서비스 고도화 / 공공데이터 활용 서비스 특허 출원 지원`

현재 자체 학습모델보다 OpenAI API 및 규칙 기반 엔진 비중이 높으므로 `AI 모델 고도화`를 최우선으로 선택하는 것은 피한다. 공공데이터 수집·품질관리·구조화와 설명형 AI의 평가기준 설계를 우선 요청하는 편이 현재 단계와 정합적이다.

## 신청서 목차별 작성 초안

### 2-1. 사업배경

임대차 의사결정에 필요한 거래·교통·지역 정보가 분산되어 있고, 비전문 사용자가 공공데이터 원문을 직접 비교하기 어렵다는 문제를 제시한다. 목표시장은 국내 온라인 임대 매물 탐색 및 계약 전 확인 시장으로 정의한다.

### 2-2. 서비스 소개

매물 주소를 기준으로 공공데이터를 결합하고 AI가 근거 있는 지역 설명을 생성하는 웹·모바일 서비스를 설명한다. 사용자 흐름은 `매물 조회 → 공공데이터 요약 → 출처 확인 → 추가 확인 항목 안내`로 제시한다.

### 2-3. 공공데이터 활용

전월세 실거래가와 법정동코드를 1차 필수 데이터로, 교통정보를 2차 확장 데이터로 쓴다. 현재는 활용 준비 단계이며 NIA 컨설팅을 통해 API 선정, schema, 정제·캐시, 품질지표를 확정한다고 사실대로 작성한다.

### 2-4. 비즈니스 모델

기본 매물 탐색은 무료, 고급 비교 리포트와 임대관리 도구는 구독형으로 제시한다. 장기적으로 임대사업자·주거서비스 사업자용 B2B 분석 리포트를 부가 수익원으로 검증한다.

### 2-5. 3년 로드맵

- 1년차: 3개 핵심 공공데이터 연동, 설명형 demo 및 품질평가 구축
- 2년차: 지역·주택유형 확대, 사용자 행동 기반 설명 품질 개선
- 3년차: B2B 리포트와 외부 주거서비스 연동 검증

매출·사용자 수는 대표자가 승인한 실제 계획값으로 채운다.

### 2-6. 기대효과

분산된 공공데이터의 실사용을 늘리고 임차인의 정보 비대칭과 탐색비용을 줄인다. 내부적으로는 공공데이터 품질관리 체계, AI 설명 평가셋, 개인정보 분리 원칙을 확보한다.

### 2-7. 필요 지원사항

공공데이터 API 선정, 주소 join 품질, 갱신·결측 처리, 설명용 feature schema, AI 사실성 평가셋, 출처 표기 UX, 공공데이터 활용 특허 범위 검토를 요청한다.
