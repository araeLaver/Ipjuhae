# 테스터 12명 채널 배분 및 일별 모집 계획

작성: 2026-09-20 / 사업개발. 상태: CEO 검토용, 게시·발송·결제 미실행. 이 문서가 배분표의 단일 원본이다.

## 확인된 기록과 미확인 사실

- 기존 기록: 명단 6명, 설치 가능 5명. 현재 Console opt-in 수·연속 참여일·실제 설치 수는 미확인이다. 5명도 확보 실적으로 확정하지 않는다.
- 기본 시나리오의 시작값 B=5는 계획 계산용 가정이다. 실행 전 실제 확인값 B로 대체하고 부족분을 max(0,12-B)로 다시 계산한다. 계정 교체 1명은 완료 확인 전 목표 달성 수에 넣지 않는다.
- 채널 접근권한, 게시 담당자, Android 실기기 D대, 사용 가능한 계정 G개, 기존 상호테스트 약속 E건은 미확인이다. 보드 확인은 [DOW-1069](/DOW/issues/DOW-1069)에 모은다.
- 문안은 `docs/TESTER_RECRUIT.md` A/B/C와 [기존 아웃리치 문안](/DOW/issues/DOW-1055#document-outreach-20260920-scripts)을 재사용한다. 아래 채널은 후보이며 게시 허용·접근권한은 확인되지 않았다.

## 집계 정의와 일정 기준

모집 전환은 고유 참여자의 closed-test opt-in과 설치·첫 실행 확인까지 완료한 경우로 정의한다. 중복 유입은 최초 채널 하나에만 배정한다. Console의 opt-in 요건 충족 여부와 내부 설치·피드백 관리는 별도 열로 기록한다.

Google 공식 요건은 신청 시 최소 12명이 직전 14일 연속 opt-in을 유지하는 것이다. 설치 유지·실사용 점검은 내부 운영 기준이며, 삭제 1회가 전체 인원의 시계를 무조건 초기화한다고 단정하지 않는다. 모집 과정·참여·피드백·개선 내용을 신청에 설명할 수 있도록 증거를 남긴다. [Google Play 공식 안내](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en) (2026-09-20 확인).

12명의 연속 참여 시작이 9/26이면 신청 가능 시점의 계획상 하한은 10/10, 9/30이면 10/14다. 정확한 시각·Console 자격 표시를 확인하며 심사·공개 완료일을 보장하지 않는다.

## 게시 후 3일 판정 규칙

1. 각 채널 첫 승인 게시·발송 시각을 T0로 기록한다. 승인 대기는 시계에 넣지 않는다.
2. T0+72시간에 신규 확인 전환이 0명이면 추가 게시·발송을 중단하고 다음 후보로 이동한다. 이미 한 상호테스트 약속은 끝까지 이행한다.
3. 유입 자체가 없으면 채널을 교체하고, 문의는 있으나 설치가 없으면 계정·초대·설치 경로를 점검한다. 중단 채널의 기존 문의 응대는 계속한다.
4. 1명 이상이어도 배분 목표에 미달하면 부족분만 예비 채널에 이관한다. 한 사람을 두 채널의 성공으로 중복 계산하지 않는다.
5. 익명 웹 방문 수를 테스터 수로 대체하지 않는다. `/check` 집계는 [DOW-1074](/DOW/issues/DOW-1074) 구현·검증 전까지 미측정으로 둔다.

## 상호테스트 왕복 한도

보드가 확인한 실기기 D, 계정 G, 14일 동안 실제 관리할 수 있는 동시 약속 H, 기존 약속 E를 사용해 보수적 신규 한도 N=max(0,min(D,G,H)-E)로 제안한다. 이는 내부 운영 상한이며 Google의 기기당 계정 규칙이 아니다. D/G/H/E가 미확인이면 N도 미확인이다.

한도 확인 전 확약은 하지 않는다. 승인 후 상호테스트 배분은 min(N,2,현재 부족분)으로 제한한다. A의 무제한 당일 설치 약속은 “수용 가능 인원을 확인한 뒤 개별 확정하고, 확정 건은 설치일부터 14일 유지합니다”로 바꾼다. 각 확약에 담당자·상대 앱·시작일·종료일·확인 상태를 기록하며 채널을 접어도 기존 의무는 유지한다.

## 9/26 유료 백스톱 검토 패키지

CEO는 검토 진행에 동의했으며 비용 집행은 승인되지 않았다. 9/26 20:00 KST에 자력으로 확인된 고유 참여자 S를 집계한다.

- S<9: 부족분 Q=max(0,12-S)에 한해 견적 비교와 집행 승인 요청. S=8이면 4명, S=5이면 7명이다.
- 9≤S<12: 부족 인원과 무료 채널 잔여 가능성을 보고하되 자동 결제하지 않는다. 9/30에도 미달이면 CEO에게 재판정을 요청한다.
- S≥12: 모집 대행 필요 없음. 참여 유지와 피드백 수집으로 전환한다.
- S 미확인: 부족분과 주문량을 확정하지 않는다. CEO가 보드의 Console 확인을 받아 판단한다.

**비용 상한 제안:** 완료 조건을 충족하는 1인당 총액 10,000원 이내, 전체 총액 min(Q×10,000원,100,000원) 이내. 세금·수수료 포함 내부 예산 제안이며 시장가격·확보 가능한 견적이 아니다. 해당 조건의 공급자가 없거나 초과 견적이면 집행 보류 후 CEO 재승인 요청. 12명 묶음만 판매하는 경우 필요 부족분과 맞지 않으면 자동 구매하지 않는다.

검토할 서비스 범위: 부족분만 모집, 실제 Android 사용자의 closed-test 참여·설치·첫 실행 확인, 참여일부터 14일 연속 opt-in 유지 안내, 1·7·14일 사용 과제와 개별 피드백, 이탈 통지 및 대체 조건, 시작·종료일 및 이행 증빙. 대체 인원은 본인의 연속 참여 기간을 새로 계산한다. 승인 보장·계정 대량 제공·별점 작성은 구매 조건에서 제외한다.

실제 피드백은 예시 숫자로 `/check` 입력→결과 이해→불편 사항 기록의 동일 과제를 자력·유료 참여자 모두에게 요청한다. 1일차 설치 장애와 첫 인상, 7일차 이해도와 재사용 문제, 14일차 개선 후 재확인을 받는다. 참여자 코드·날짜·앱 버전·재현 단계·의견·수정 내역·재확인 결과를 남기고 개인 계정 주소는 이 계획이나 공개 댓글에 넣지 않는다. 사업개발이 원문 의견을 종합하고 기술 결함은 담당 개발자에게 전달한다. 복제된 한 줄 평가나 설치 숫자만으로 완료 처리하지 않는다.

9/26 제출 양식: `확인 시각 / S / Q / 채널별 실적 / 후보별 총 견적 / 제공 인원 / 14일 유지 조건 / 피드백 방식 / 이탈·환불 조건 / 권고안`. 공급자·가격은 현재 미조사·미확정이다.

## 승인과 다음 담당자

CEO 검토 요청: 배분 가설, 일별 목표, 유료 대행 상한 제안 승인 여부. 보드 확인 및 실제 게시·발송 승인은 [DOW-1069](/DOW/issues/DOW-1069)에서 회수한다. CEO가 계획 검토 후 사업개발에 실행 준비를 재배정한다. 기존 이슈를 사용하며 중복 모집 문서를 만들지 않는다.

실행 전 기록표: `날짜·시각 | 채널 | 담당자 | 게시/발송 수 | 도달(측정/추정/미측정) | 문의 | 고유 opt-in | 설치·첫 실행 | 이탈 | 신규/누적 | 다음 판정 시각`. 시작 실적은 미확인으로 유지하며 수치를 꾸며 채우지 않는다.
