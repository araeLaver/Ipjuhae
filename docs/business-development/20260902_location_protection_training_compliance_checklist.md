- 기준일: 2026-09-02
- 결론: **교육 참석 가능, 외부 신청은 보드 승인 후 진행**
- 적용 판단: 현재 입주해는 고정 부동산 주소를 처리하지만 단말 위치·이동경로를 측위하지 않아 위치정보법상 개인위치정보 처리 가능성은 낮다.
- 주의: 사업개발 사전 점검이며 법률의견이 아니다.

KISA는 위치정보관리책임자와 위치정보취급자 전체에게 연 1회 정기교육을 권고한다. KISA 교육 참석 시 수료증을 증빙으로 보관할 수 있다. 개인정보보호 교육으로 대체할 수 없으며, 함께 진행하더라도 위치정보 교육 내용과 증빙이 별도로 남아야 한다.

## 2. 현재 제품 기준선

| 확인 항목 | 저장소 근거 | 현재 판정 |
| --- | --- | --- |
| 단말 현재 위치 | `next.config.js`에서 `Permissions-Policy: geolocation=()` | 수집 차단 |
| GPS·좌표·이동경로 | `latitude`, `longitude`, `getCurrentPosition`, `watchPosition` 구현 없음 | 미처리 |
| 매물 위치 | 도로명·지번 주소와 상세주소를 입력·저장 | 고정 부동산 주소; 개인정보 관리는 필요 |
| 검색·추천 | 주소 문자열·선호 지역 기준 매칭 | 측위정보 사용 근거 없음 |
| 공개 범위 | 공개 화면/API는 일반 주소, 상세주소는 소유자 관리 범위 | 최소공개 정책 존재 |
| 삭제·파기 | 매물 삭제 또는 탈퇴 시 삭제; 계약 리포트 FK가 있으면 주소를 비식별화 | 파기 경로 구현됨 |

따라서 현재는 아래 체크리스트 중 `현행 주소 처리` 항목을 운영하고, `개인위치정보 기능 도입 시` 항목은 출시 전 필수 게이트로 사용한다.

## 4. 이용 체크리스트

- [ ] 목적별 API와 DB 접근권한을 최소화하고 위치정보취급자 목록을 관리한다.

- [ ] 정확한 좌표가 필요하지 않은 기능은 행정구역·거리 구간 등으로 축소한다.
- [ ] 동의 철회·처리 정지 시 후속 추천과 캐시에서도 사용을 중단한다.

- [ ] 제3자 제공과 처리위탁을 구분하고 필요한 동의·고지·계약을 적용한다.

- [ ] 공유 링크에는 만료, 철회, 재공유 제한, 최소 정밀도를 적용한다.

- [ ] 수사기관 등 법적 요청은 근거·범위·승인·제공 내역을 기록한다.

- [ ] 위치정보관리책임자와 위치정보취급자를 지정하고 취급·관리 지침을 승인한다.
- [ ] 취급자 전원에게 연 1회 이상 위치정보 교육을 시행하고 수료증 또는 계획·자료·참석확인·사진을 보관한다.
- [ ] 전송·저장 구간 암호화, 비밀키 분리, 접근통제, 관리자 MFA를 적용한다.
- [ ] 위치정보 수집·이용·제공사실 확인자료의 생성 항목과 법정 보존기간을 법률 검토 후 확정한다.
- [ ] 접속기록의 위변조 방지, 정기 점검, 이상 접근 경보와 사고대응 절차를 운영한다.
- [ ] 개발·분석 환경에는 실좌표 대신 합성·비식별 데이터를 사용한다.
- [ ] 수탁자 보호조치와 재위탁 통제, 정기 점검권을 계약에 포함한다.
- [ ] 정기 권한 재검토와 퇴직·직무변경 시 즉시 권한 회수를 수행한다.

## 7. 파기 체크리스트

- [ ] 목적 달성, 보유기간 만료, 동의 철회 시 원시 위치정보와 파생 데이터를 지체 없이 파기한다.
- [ ] DB뿐 아니라 캐시, 검색 인덱스, 분석 저장소, 로그, export, 백업의 파기 일정을 정의한다.
- [ ] 법정 보존자료는 운영 데이터와 분리해 목적 외 접근을 차단한다.
- [ ] 계정 삭제 API와 위치정보 삭제 작업을 연결하고 이용자에게 처리 결과를 알린다.
- [ ] 삭제 작업 실패를 탐지·재시도하고 완료 증적을 남긴다.
- [ ] 비식별화로 대체할 때 재식별 위험과 잔존 정밀도를 검증한다.

## 8. 출시 전 Go/No-Go 게이트

다음 중 하나라도 도입하면 위치정보 기능으로 분류해 법무 검토가 끝날 때까지 출시하지 않는다.

- 사용자 현재 위치 기반 주변 매물 검색
- 통근거리 추천을 위한 단말 위치 또는 이동경로 수집
- 실시간 위치 공유·안전 체크인
- GPS가 부착된 이동 물건 또는 개인 위치 데이터 연동
- 지도 SDK/API로 사용자 시점별 위치를 서버에 전달

출시 Go 조건은 사업자 등록·신고 적용성, 동의·약관·처리방침, 보호조치, 이용자 권리, 제공·통보, 보관·파기 설계에 대한 법무 확인과 보안 QA 완료다.

1. 고정 부동산 주소·상세주소만 처리하는 현행 서비스가 위치정보법상 `위치정보` 또는 `개인위치정보`에 해당하는가?
2. 사용자 현재 위치를 일시적으로 단말에서만 사용하고 서버에 전송하지 않는 주변 검색도 위치기반서비스사업 신고 대상인가?
3. 입주해의 법인·사업자 형태에 적용 가능한 등록·신고 의무 또는 소상공인·1인 창조기업 특례는 무엇인가?
4. 사용자 위치와 선호 지역을 결합한 추천에 필요한 동의 문구와 별도 동의 범위는 어디까지인가?
5. 지도·지오코딩·분석 사업자로 좌표를 보내는 경우 처리위탁과 제3자 제공을 가르는 기준은 무엇인가?
6. 위치정보 수집·이용·제공사실 확인자료에 반드시 포함할 항목과 정확한 보존기간은 얼마인가?
7. 동의 철회와 계정 삭제 시 백업·로그·파생 추천 데이터는 어느 시점까지 어떤 방식으로 파기해야 하는가?
8. 상세주소 비공개와 비식별화 방식이 개인정보보호법상 최소조치로 충분한가?
9. 위치 공유·안전 기능에서 상대방 동의, 제공 통보, 오남용 방지에 필요한 제품 통제는 무엇인가?
10. 개인정보처리방침과 별도로 위치정보 이용약관 및 개인위치정보 처리방침을 공개해야 하는 정확한 기능 분기점은 무엇인가?
