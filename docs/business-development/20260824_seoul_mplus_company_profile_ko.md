## 1장. 임차인 프로필에서 시작하는 역방향 임대 매칭

**입주해(Rentme)**  
임차인의 조건을 먼저 구조화하고, 적합한 임대 매물을 설명 가능한 기준으로 연결합니다.

- 단계: Next.js·TypeScript 기반 MVP
- 제안 대상: 베트남 임대운영사·부동산 플랫폼
- 제안 범위: 합성 데이터 기반 4주 workflow PoC

## 2장. 문제 — 임대 후보 검토는 반복적이고 기준이 흩어져 있습니다

- 임차인은 여러 매물을 반복 탐색하고 같은 조건을 다시 입력합니다.
- 운영자는 예산, 입주일, 생활조건 등 서로 다른 항목을 수작업으로 비교합니다.
- 판단 이유가 남지 않으면 재검토와 담당자 간 인수인계가 어렵습니다.
- 실제 개인정보를 조기에 공유하면 규제와 보안 위험이 커집니다.

**PoC 질문:** 구조화된 profile과 설명 가능한 ranking이 후보 검토시간과 누락을 줄일 수 있는가?

## 3장. 제품 — 조건별 점수와 불충족 사유를 함께 보여줍니다

1. 임차인이 예산, 선호 지역, 입주일과 생활조건을 입력합니다.
2. 매물 조건과 비교해 예산, 신용/신뢰 입력값, 입주일, 생활조건, 고용 조건을 평가합니다.
3. 총점만이 아니라 조건별 점수, 적합 사유와 `dealbreakers`를 반환합니다.
4. 운영자는 결과를 검토하고 다음 대화로 이어갈 수 있습니다.

화면 삽입 제안: 프로필 입력 → matching 결과 → 사유/불충족 항목의 3단 흐름. 실제 공개 가능한 제품 캡처만 사용합니다.

## 4장. 차별점 — 검색 서비스가 아니라 검토 workflow입니다

| 일반 매물 검색 | 입주해 workflow |
|---|---|
| 매물을 먼저 탐색 | 임차인 조건을 먼저 구조화 |
| 필터 통과 여부 중심 | 점수와 사유, 불충족 조건 함께 제시 |
| 담당자의 수작업 비교 | 반복 가능한 평가 기준 제공 |
| 개인정보 연동을 전제할 수 있음 | PoC는 합성·비식별 데이터로 시작 |

입주해는 신용평가나 자동 계약을 주장하지 않습니다. 최종 판단은 운영자가 수행하며, 제품은 검토를 보조합니다.

## 5장. FPT와 검증할 4주 PoC

- **1주차:** 현행 workflow와 data boundary 정의
- **2주차:** 합성 tenant profile·매물 각 30건 현지화
- **3주차:** matching 실행과 현업 평가
- **4주차:** 기준선 비교, 규제·제품 gap, 후속 Go/No-Go

평가지표는 검토시간, Top-N 일치율, 필수 입력 누락 탐지율, 설명 이해도입니다. 목표치는 현업 기준선 확인 후 공동 합의합니다.
