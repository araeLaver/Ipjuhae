## 1. 현재 판정

**제출 보류(확인값 회수 후 조건부 Go)**다. 공식 공고의 모집기간, 행사 일정, 업력 요건과 지원 내용은 확인했으나, 법인·세무·수혜 이력·참석자·실제 traction을 증빙할 자료가 현재 저장소에 없다. Google Forms는 로그인 화면까지만 접근되어 파트너별 상세 모집 수요도 확인하지 못했다.

따라서 지금 제출하면 자격 또는 사실표현 오류 위험이 있다. 아래 게이트를 보드가 확인하고, 로그인 후 실제 수요 문구를 대조한 뒤에만 최종 Go로 전환한다.

## 3. 보드 회신표

민감한 상세 주소, 사업자등록번호, 개인 연락처와 증빙 원문은 Git이나 Paperclip 댓글에 기록하지 않는다. 보드는 아래의 `확인/불충족`과 공개 가능한 범위만 회신한다.

| 게이트 | 회신값 | 판정 기준 |
|---|---|---|
| 사업자등록증상 법인/사업자명 | `[대외 표기명]` | 신청서·소개서 표기 일치 |
| 설립일 | `[YYYY-MM-DD]` | 공고일 기준 업력 7년 미만 |
| 소재지 | `[시·도/시·군·구 수준]` | 전국 소재 |
| 국세 체납 없음 | `[확인/불충족]` | 최신 납세증명서 또는 대표 확인 |
| 지방세 체납 없음 | `[확인/불충족]` | 최신 납세증명서 또는 대표 확인 |
| 동 사업 기존 수혜 없음 | `[확인/불충족/문의 필요]` | 같은 대형유통사를 통한 기존 수혜가 없어야 함 |
| 10월 7~8일 BEXCO 참석 | `[가능/불가]` | 참석자 성명은 신청 시스템에서만 입력 |
| 공개 가능한 사용자 수 | `[숫자+기준일/없음]` | 관리자·테스트 계정 제외, 근거 보유 |
| 공개 가능한 인터뷰 수 | `[숫자+기준일/없음]` | 인터뷰 기록 보유 |
| 공개 가능한 파일럿·고객·매출 | `[숫자+기준일/없음]` | 계약·운영·결제 근거 보유 |
| 공개 가능한 MVP URL | `[URL/비공개]` | 실제 접근 가능한 경우만 사용 |

한 항목이라도 자격 불충족이면 **No-Go**다. traction이 없거나 미확정이면 숫자를 만들지 않고 `동작 가능한 MVP 및 PoC 준비 단계`로만 표현한다.

선택 규칙은 다음과 같다.

1. 실제 수요에 주거, PropTech, 임대차 운영, 문서 확인, 보험상담 준비, 금융상담 준비 중 하나가 명시되면 우선 검토한다.
2. 금융상품 추천·대출심사·보험 인수·신용평가·법률판단을 요구하면 현재 범위와 불일치하므로 No-Go다.
3. 현대건설·DB손해보험·하나은행 중 불일치 파트너가 있으면, 문서 AI 또는 신뢰 workflow 수요가 명시된 경우에만 네이버클라우드로 교체한다.
4. 최종 신청은 최대 3개 파트너로 제한한다.

## 5. 파트너별 최종 제안안

### 현대건설

- 제안 1문장: 현대건설의 임대주거 운영 과정에 입주해의 임차인·임대인·주택 3축 확인 리포트를 적용해 계약 전 확인 누락과 운영자 반복 검토를 줄이는 PoC를 제안한다.
- 범위: 4주, 합성 임대차 사례 20건, 임대운영 담당자 2~3명, 개인정보 없는 확인상태표·미확인 사유·다음 행동 제공
- KPI: 사례당 검토시간, 필수항목 누락 발견률, 담당자 수정률, 리포트 이해도
- 성공 기준: 기준선 대비 검토시간 20% 감소 또는 누락 발견률 20% 향상, 중대한 개인정보·표시 리스크 0건

### DB손해보험

- 제안 1문장: 입주해의 증빙 기반 임대차 확인상태를 활용해 보험 검토 전 필수정보 누락과 전문가 상담 필요 시점을 구조화하는 탐색 PoC를 제안한다.
- 범위: 4주, 합성 사례 30건, 현업·준법 담당자 검토, 상품 추천이 아닌 `추가 확인 필요/전문가 상담 필요` 상태만 제공
- KPI: 상담 전 필수정보 완성도, 현업 기준 일치율, 오탐률, 준법 수정 건수
- 진입 조건: 대상 업무·현업 오너·비민감 필드·준법 검토 경로 합의

### 하나은행

- 제안 1문장: 전월세 상담 전 고객의 계약·주택 확인자료를 출처·기준일·확인상태로 정리해 반복 질문과 서류 누락을 줄이는 비식별 탐색 PoC를 제안한다.
- 범위: 현업·준법 인터뷰 2회 후 합성 사례 20건의 상담 전 체크리스트 사용성 검증
- KPI: 반복 질문 수, 필수자료 누락률, 사용자 이해도, 준법 수정 건수
- 제외: 대출 가능성·금리·한도 예측, 신용점수 생성, 실제 고객정보/API 연동, 금융상품 자동 추천

### 네이버클라우드 교체안

- 제안 1문장: 네이버클라우드의 문서 AI 기술과 입주해의 증빙·검수·감사 workflow를 결합해 임대차 문서의 필드 추출 정확도와 운영자 검수 효율을 검증하는 PoC를 제안한다.
- 범위: 개인정보 없는 합성 문서 50건, OCR/필드 추출, 검수 화면, 오류 유형 기록
- KPI: 필드별 정확도, 검수 소요시간, 재처리율, 설명 가능한 오류 기록률
- 진입 조건: 실제 모집 수요에 document AI, OCR, workflow 또는 vertical SaaS 협업이 명시될 것

## 6. 외부 표현 경계

- 제품 근거로 `Next.js·TypeScript 기반 동작 가능한 MVP`, 자동화 테스트, smoke QA는 사용할 수 있다.
- 이 근거를 실제 사용자·고객·매출·파트너십 traction으로 바꾸어 표현하지 않는다.
- `신뢰 점수`, `보험 위험 분류`, `대출 적격 판단`, `법률 안전성 보장`, `자동 중개` 표현은 사용하지 않는다.
- 실제 시장 traction 증빙이 없으면 `합성 데이터 기반 PoC 준비 단계`로 표시한다.

## 7. 제출 직전 순서

1. 보드 회신표의 자격·참석·traction 값을 확정한다.
2. 로그인 후 파트너별 실제 수요를 전사하고 적합성을 재판정한다.
3. 최대 3개 파트너와 각 제안문·PoC·KPI를 확정한다.
4. 신청서·one-pager의 법인명, 설립일, 제품 단계, 모든 숫자를 증빙과 대조한다.
5. 보드가 최종 제출을 명시적으로 승인한 뒤에만 Google Forms에 입력·제출한다.
6. 제출 완료 화면과 접수 이메일을 보관한다.
