# 임대차 리스크 리포트 내부 dry-run 결과

작성일: 2026-08-31  
검증 대상: `20260831_rental_risk_customer_validation_pack.md`의 B2C/B2B 1페이지 mock  
안전 경계: 합성 데이터만 사용했으며 외부 연락·결제·실제 개인정보 입력은 수행하지 않았다.

## 1. 방법과 판정 기준

- 역할 A: 첫 독립 계약을 앞둔 임차인. B2C mock을 설명 없이 최대 3분 읽고 핵심 상태, 위험 신호, 다음 행동을 회상했다.
- 역할 B: 독립 QA가 소형 중개·임대운영 담당자 역할로 B2B mock을 설명 없이 최대 3분 읽고 처리 상태, 미확인 항목, 담당자 조치를 회상했다.
- 성공: 핵심 상태 1개, 위험 또는 결손 2개 이상, 구체적인 다음 행동 1개 이상을 정확히 회상하고 안전·사기·법률 판정으로 오해하지 않아야 한다.

## 2. 역할 A — 임차인 관점 관찰

### 회상 결과

| 항목 | 관찰 | 판정 |
|---|---|---|
| 핵심 상태 | `추가 확인 필요`를 즉시 인지 | 성공 |
| 위험·결손 | 보증금이 비교 표본보다 높음, 등기자료 없음, 보증 사전확인 안 됨의 3개를 회상 | 성공 |
| 다음 행동 | 최신 등기사항증명서 확인과 보증기관 요건 확인을 선택 | 성공 |
| 오해 여부 | 계약 중단·사기 판정이 아니라 확인 과제가 남은 상태로 이해 | 성공 |
| 읽기 시간 | 약 2분 내 핵심 표와 질문 문구 확인 가능 | 성공 |

### 마찰과 오해 가능성

- `보증금 수준`의 9% 차이가 왜 위험한지 기준이 없다. 현재 문구만 보면 9% 초과 자체가 위험 임계값처럼 읽힌다.
- `추가 확인 필요`는 세 항목 모두에 걸친 종합 상태처럼 보이지만, 실제로는 가격 비교와 자료 결손의 성격이 다르다.
- 세 번째 질문의 `보증 가입이 불가능하면 계약금 반환`은 유용한 협의 질문이지만, 특약만 있으면 반환이 보장되는 것으로 확대 해석될 수 있다.
- `임대인 신분 확인`은 구현 단계에서 신분증 이미지 업로드를 유도할 수 있다. 원본 대면 확인 또는 공식·승인된 채널 확인으로 제한하고 이미지 저장 금지를 명시해야 한다.

## 3. 역할 B — 중개·운영 관점 독립 QA 관찰

### 회상 결과

| 항목 | 관찰 | 판정 |
|---|---|---|
| 핵심 상태 | `조건부 등록 권고`를 등록 가능한 상태 또는 서비스 승인으로 해석할 여지가 큼 | 실패 |
| 위험·결손 | 소유자 일치, 선순위 권리, 보증 가능성의 3개를 회상 | 성공 |
| 다음 행동 | 원본 확인, 채권최고액·시세 대비 비율 확인, 보증요건 조회를 선택 | 성공 |
| 오해 여부 | `권고`가 서비스의 승인·안전 판단처럼 보일 수 있음 | 실패 |
| 개인정보 | `원본 대면/공식 채널 확인`은 적절하나 보관 금지 규칙이 없음 | 보완 필요 |

### 마찰과 오해 가능성

- 필수자료 6개 중 `소유자 일치`가 미확인이고 근저당도 표시된 상태에서 `조건부 등록 권고`는 너무 강한 결론이다.
- `선순위 권리`의 조치가 `시세 대비 비율 확인`이지만 표 안에는 시세·채권최고액·산식·판정 주체가 없어 즉시 실행하기 어렵다.
- `확인됨`과 `미확인` 사이에 `추가 확인`이 있어 상태 체계가 중복되어 보인다. `확인 / 자료 없음 / 검토 필요`처럼 원인 중심으로 분리하는 편이 낫다.
- `고객설명용 문구`는 그대로 복사할 가능성이 높으므로 기준일, 출처, 담당자 승인 여부를 문구 바로 옆에 강제 표시해야 한다.

### 위험도

**High** — 미확인 매물을 승인·안전하다고 오해할 수 있고, 현재 문구로 인터뷰하면 문구 자체가 응답을 유도해 고객가치 검증 결과까지 왜곡할 수 있다.

## 4. 외부 인터뷰 전 필수 수정

1. B2B 제목을 `처리 결과: 등록 판단 보류`로 바꾸고, 소유자 일치·권리·보증 가능성 확인 전에는 등록 또는 안전 여부를 권고하지 않는다고 명시한다.
2. B2C 가격 신호를 `비교 참고`로 낮추고 `9%는 위험 임계값이 아님`, 표본수·기간·면적 조건을 같은 행에 표시한다.
3. 상태 체계를 결과와 근거로 분리한다. 결과는 `판단 보류 / 확인 과제 있음`, 근거 상태는 `확인 / 자료 없음 / 검토 필요`로 제한한다.
4. 신분 확인 문구에 `신분증 이미지 업로드·복사·저장 금지`, `원본 대면 또는 승인된 공식 채널에서만 확인`을 추가한다.
5. 특약 문구 뒤에 `특약의 효력과 반환을 보장하지 않으며 필요 시 공인중개사·법률전문가에게 확인`을 붙인다.
6. 고객설명 문구에 근거의 출처·발급일·담당자 승인 상태를 필수 필드로 붙인다.
7. `채권최고액·시세 대비 비율`의 입력값, 산식, 기준일, 판정 주체가 없으면 결과를 표시하지 않는다.
8. B2B synthetic JSON의 `expectedOutcome`을 `등록 판단 보류`로 바꿔 회귀 시 기존 위험 문구가 재생성되지 않게 한다.

## 5. 선택 수정

- 첫 화면의 세 신호를 `가격 비교`, `권리자료`, `보증요건`으로 묶고 각 카드에 한 가지 행동만 둔다.
- `미입력`을 `현재 리포트에 제공되지 않음`으로 바꿔 사용자의 입력 책임처럼 느껴지는 인상을 줄인다.
- B2B 운영효과의 `10분 이하`는 검증 전 목표값임을 배지로 구분한다.
- 고객설명 문구 옆에 `담당자 검토 전 고객 제공 금지`를 배치한다.
- 3분 검증과 별도로 5초 노출 테스트에서는 제목·상태·첫 행동만 측정해 지표를 혼합하지 않는다.

## 6. 현재 게이트 판정

- B2C: **조건부 통과** — 핵심 이해와 행동 전환은 성공했으나 가격 임계값·특약·신분 확인 문구를 외부 노출 전에 수정해야 한다.
- B2B: **수정 후 재검수** — 위험 항목은 이해되지만 `조건부 등록 권고`가 승인 또는 안전 판단으로 오인될 가능성이 있어 현재 문구로 외부 인터뷰를 진행하지 않는다.
- 전체: **외부 인터뷰 보류** — 필수 수정 8건 반영 후 같은 절차로 `등록 판단 보류`의 정확한 회상과 승인·안전 오인 0건을 재검증한다.
