# 입주해·Rentme 상표 선행검색 준비표 및 IP 체크리스트

- 작성일: 2026-08-30
- 용도: KIPRIS 직접 검색과 변리사 상담 전 내부 준비
- 범위: 검색·기록·권리관계 점검만 수행하며, 출원 가능성에 대한 법률의견이나 등록 보장을 뜻하지 않는다.

## 1. 먼저 결정할 사항

1. 국내 주 브랜드를 `입주해`로 유지할지, `Rentme`를 병기·독립 브랜드로 사용할지 결정한다.
2. 실제 출시 시점에 제공할 서비스만 기준으로 지정서비스를 좁힌다.
3. 문자상표를 우선 검토하고, 로고가 확정된 뒤 별도 도형·결합상표를 검토한다.
4. KIPRIS 검색 결과의 동일·근접 표장은 출원번호, 상태, 권리자, 지정상품, 유사군코드까지 기록해 변리사에게 전달한다.

## 2. 검색 표장 후보

| 우선순위 | 표장 | KIPRIS 입력 후보 | 확인 목적 |
|---|---|---|---|
| 1 | 입주해 | `입주해`, `입주 해`, `입주*해` | 동일·띄어쓰기·중간문자 변형 |
| 1 | RENTME | `RENTME`, `RENT ME`, `RENT*ME` | 영문 동일·띄어쓰기 변형 |
| 2 | 렌트미 | `렌트미`, `렌트 미`, `렌트*미` | 영문 표장의 한글 음역 |
| 2 | IPJUHAE | `IPJUHAE`, `IPJU HAE`, `IPJU*HAE` | 한글 표장의 로마자 표기 |
| 3 | 입주헤·입주혜 | 각 표기 및 `입주*` | 발음·외관이 가까운 오기 후보 |
| 3 | RENT-ME·RENTMI | 각 표기 및 `RENT*` | 하이픈·철자 근접 후보 |

검색은 한 번에 결론내지 않고 다음 순서로 반복한다.

1. 상표명칭만으로 전체 류를 검색해 동일·저명 표장을 확인한다.
2. 후보 류를 적용해 검색한다.
3. 각 지정서비스에서 확인된 유사군코드로 다시 검색한다.
4. 동일 표장뿐 아니라 호칭·관념·외관이 가까운 결과를 사람이 검토한다.
5. `출원`, `공고`, `등록`, `소멸`, `거절` 등 법적 상태와 기준일을 함께 기록한다.

KIPRIS는 띄어쓰기를 무시하고 자동 절단검색을 적용할 수 있으므로, 결과 화면의 실제 검색식과 결과 건수를 캡처한다. 유사군코드는 상품·서비스의 유사범위를 표시하는 식별기호이며 일부 항목에는 복수 코드가 붙을 수 있다.

## 3. 상품·서비스류 초안

아래는 출원 문구가 아니라 검색 출발점이다. 최신 고시의 정확한 명칭과 유사군코드는 KIPRIS 상품분류 입력정보 도우미에서 확정해야 한다.

| 검토순위 | 류 | 제품과의 연결 | 직접 확인할 지정상품·서비스 검색어 | 채택 조건 |
|---|---:|---|---|---|
| 핵심 | 36 | 부동산·임대차 관련 정보 제공 또는 중개 | `부동산정보제공업`, `부동산임대업`, `부동산중개업`, `부동산관리업` | 실제 제공 기능과 법적 인허가 범위에 맞는 항목만 채택 |
| 핵심 | 42 | 웹 기반 SaaS, 소프트웨어 개발·대여 | `SaaS`, `PaaS`, `컴퓨터소프트웨어대여업`, `컴퓨터소프트웨어개발업`, `웹사이트호스팅업` | 구독형 웹서비스 또는 소프트웨어 제공이 실제 사업 범위인 경우 |
| 조건부 | 9 | 다운로드 가능한 앱·소프트웨어 | `다운로드 가능한 모바일 애플리케이션`, `컴퓨터소프트웨어` | App Store/설치형 앱 배포가 확정된 경우 |
| 조건부 | 35 | 광고·사업정보·온라인 비교/마켓플레이스 지원 | `광고업`, `사업정보제공업`, `온라인 비교쇼핑서비스업` | 부동산업 자체와 구분되는 광고·사업지원 매출모델이 있는 경우 |
| 보류 | 45 | 법률정보 또는 안전 관련 서비스 | `법률정보제공업` 등 | 법률서비스로 오인되지 않도록 실제 제공 주체·책임 구조를 법률 검토한 뒤 판단 |

공식 Nice 분류의 큰 범위상 제36류는 부동산업, 제42류는 컴퓨터 하드웨어·소프트웨어의 디자인 및 개발업을 포함한다. 류가 같다고 곧 유사한 것은 아니고, 류가 다르다고 반드시 비유사한 것도 아니므로 지정서비스와 유사군코드 확인이 핵심이다.

### 중단·상담 기준

- 동일 또는 매우 가까운 표장이 핵심 지정서비스에 `출원·공고·등록` 상태로 존재한다.
- 핵심 지정서비스의 유사군코드가 겹치고 거래경로·수요자도 가깝다.
- 표장의 식별력이 약해 독점범위가 불명확하거나, 타인의 저명 표장과 연상이 생긴다.
- 검색 결과 상태·권리범위를 내부에서 해석하기 어렵다.

위 경우 이름 사용 확대나 외부 공개 전에 변리사 검토를 받는다. `검색 결과 없음`은 등록 가능 또는 침해 부재를 보장하지 않는다.

## 5. IP·라이선스 권리귀속 체크리스트

### 코드·기술

- [ ] 모든 commit의 작성자와 실제 기여자를 식별할 수 있다.
- [ ] 직원·공동창업자 계약에 직무 범위, 산출물 귀속, 비밀유지, 퇴사 후 자료반환이 명시돼 있다.
- [ ] 외주 계약에 소스코드, 문서, 디자인, DB 스키마 등 산출물의 저작재산권 양도 또는 충분한 이용허락과 2차적저작물 작성 권한이 명시돼 있다.
- [ ] 대금 지급이나 NDA만으로 저작권 이전을 가정하지 않는다. 프로그램 개발 위탁에서도 명시적 이전 약정이 없으면 발주자가 권리를 취득하지 못할 수 있다.
- [ ] AI 생성 코드·문구·이미지는 사용 도구, 입력 자료, 생성일, 사람의 검토·수정 내역을 기록한다.
- [ ] 영업비밀 후보(알고리즘, scoring rule, 운영 절차)는 접근권한·반출통제·비밀표시·퇴사자 회수 절차를 적용한다.

### UI·브랜드·콘텐츠

- [ ] 로고, icon, font, stock image, illustration별 원본 출처와 상업적 이용·수정·재배포 조건을 기록한다.
- [ ] 디자이너·외주 제작물의 원본 파일 인도와 저작재산권 범위를 계약서로 확인한다.
- [ ] `입주해`, `Rentme`, domain, SNS handle, App Store 명칭의 명의자와 갱신 계정을 회사 관리표에 기록한다.
- [ ] 사용자 후기·매물 사진·설명문을 공개·마케팅에 재사용할 동의 범위와 삭제 절차가 있다.
- [ ] 제3자 상표·부동산 플랫폼 화면·지도 tile을 캡처 또는 홍보물에 사용할 권한이 있다.

### 문서·DB·데이터

- [ ] 기획서, pitch deck, 정책 문서, 계약서 template의 작성자·작성일·버전·외부 반입 여부를 기록한다.
- [ ] DB는 필드별 출처, 수집 근거, 갱신주기, 원본/가공 여부, 재배포 가능 여부를 관리한다.
- [ ] DB 구조의 독자성 및 상당한 투자를 입증할 설계·정제·검수 기록을 보존한다.
- [ ] 외부에서 받은 CSV·API 응답·scraping 결과를 `출처 불명` 상태로 production에 넣지 않는다.
- [ ] 개인정보의 처리 근거·보유기간·파기와 IP 이용권한을 별개로 검토한다.

### Open Source·SaaS

- [ ] `package-lock.json` 기준 직접·전이 dependency의 license inventory와 notice 의무를 release마다 생성한다.
- [ ] GPL/AGPL/SSPL 등 copyleft 또는 source-available 조건이 포함됐는지 별도 검토한다.
- [ ] repository 최상위에 자체 코드의 `LICENSE` 또는 비공개 소유권 고지가 있는지 결정한다. 현재 `package.json`에는 `license` 필드가 확인되지 않으므로 출시 전 명시한다.
- [ ] API·cloud·AI·map·payment 제공자의 약관에서 입력데이터, 출력물, log, 재학습, 하위처리자 조건을 기록한다.

### 공공데이터

- [ ] API 또는 dataset마다 정확한 제공기관·서비스명·URL·이용허락 유형·확인일을 기록한다.
- [ ] 공공누리 유형 또는 개별 이용약관의 출처표시, 변경금지, 상업적 이용금지 등 조건을 화면·문서에 반영한다.
- [ ] 제3자 권리, 개인정보, 영업비밀이 섞인 항목과 제공기관이 권리를 보유하지 않은 콘텐츠를 제외한다.
- [ ] 호출 제한, cache·저장·재배포 허용 범위, 데이터 갱신·폐기 의무를 운영 runbook에 넣는다.
- [ ] `공개되어 있음`을 `무제한 재사용 가능`으로 해석하지 않으며, 활용 예정 데이터와 production 사용 데이터를 구분한다.

## 7. 보드 실행 순서

1. 위 표장 후보를 KIPRIS에서 전체 류 → 제36류·제42류 → 확인된 유사군 순으로 검색한다.
2. 제9류·제35류는 실제 출시·수익모델이 확정된 경우 추가한다.
3. 검색 기록과 위험표시가 있는 결과를 한 폴더에 저장한다.
4. 브랜드 우선순위, 법인·출원인 명의, 실제 제공서비스 목록을 확정한다.
5. 변리사에게 동일·근접 결과와 지정서비스 초안을 보내 출원 표장·류·문구를 검토받는다.
6. 동시에 권리대장을 만들고, 출처·계약이 불명확한 자산은 release 전 교체 또는 권리 확보한다.
