## 2. 입주해 적합성 및 데이터 활용 시나리오

입주해는 임대차 계약 전 확인 누락을 줄이기 위해 임차인·임대인·주택을 분리하고, 민감한 원본 대신 출처·기준일·검수상태가 있는 확인값과 다음 행동을 제공하는 주거 신뢰 플랫폼이다. 신청서상 **마이데이터 비즈니스 도입 단계 / 개인데이터 중심**으로 기재하는 안이 현재 제품 설명과 가장 잘 맞는다.

제안 시나리오는 정보주체의 명시적 동의를 전제로 본인확인, 재직·소득 범위 등 임차인 측 자료와 임대인·주택 관련 확인자료를 수집하고, 목적별 최소항목만 확인값으로 변환하여 계약 상대방 또는 권한 있는 중개·관리 주체에게 제한적으로 제공하는 것이다. 원본자료는 상대방에게 공개하지 않고, 동의 범위·열람 이력·정정/철회·보유기간을 관리한다. 공공·민간 API 자동연계는 확정 사실이 아니라 컨설팅을 통해 타당성을 검토할 확장 계획으로 구분한다.

## 3. 컨설팅 요청 질문

1. 임대차 계약 전 확인 서비스가 개인정보 전송요구권 기반 마이데이터에 해당하는 범위와, 단순 동의 기반 자료제출·검증 서비스로 구분되는 경계는 무엇인가?
2. 임차인·임대인·주택 3분리 확인값을 만들 때 처리 목적, 법적 근거, 최소수집, 보유기간을 데이터 항목별로 어떻게 설계해야 하는가?
3. 원본 비공개형 확인값을 제3자에게 제공할 때 별도 동의, 고지, 열람로그, 정정·철회 절차를 어떤 구조로 구현해야 하는가?
4. 신용정보·소득·재직·주택 권리관계 데이터를 연계할 경우 필요한 라이선스, 위수탁, 제휴 및 API 계약의 우선순위와 PoC 범위는 무엇인가?
5. 신용평가·법률판단·중개행위로 오인되지 않으면서 수익화 가능한 B2C 리포트, B2B 구독, 중개·임대관리 API 모델의 단계별 실행안은 무엇인가?

## 4. Go/No-Go 판단

**조건부 Go**다. 지원대상과 컨설팅 트랙에는 부합 가능성이 높고, 현재 제품의 핵심 과제가 BM·시스템·법제도 컨설팅 범위와 직접 맞닿아 있다. 다만 아래 세 조건을 2026-08-25까지 확인하지 못하면 이번 회차는 No-Go로 전환한다.

- 최신 사업자등록증 제출 가능 여부 및 신청 기관유형 확인
- 대표 포함 교육 참석자 2인 확보와 개인데이터 트랙 2026-10-29~10-30 양일 참석 가능 여부
- 신청서에 기재할 실제 보유·처리 데이터, 이용자·PoC 현황, 외부 연계 상태를 증빙 가능한 사실로 확정
