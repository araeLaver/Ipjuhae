# 2026 위치정보 맞춤형 컨설팅 적용성 및 규제 갭 점검

- 기준일: 2026-08-24
- 결론: **현재 신청 No-Go, 위치기반 기능 도입 결정 시 재검토**
- 성격: 사업개발 사전검토이며 법률의견이 아님

## 1. 결론 요약

현재 저장소에서 확인되는 위치 관련 처리는 `Daum Postcode` SDK로 검색한 **고정된 주택의 도로명·지번 주소**와 사용자가 별도로 입력한 상세주소를 매물 정보로 저장·검색·표시하는 수준이다. 브라우저 또는 모바일 단말의 GPS, `navigator.geolocation`, 실시간 좌표, 이동경로, 특정 시점의 사용자 위치를 수집하는 구현은 확인되지 않았다.

현행 위치정보법상 위치정보는 이동성이 있는 물건 또는 개인이 특정 시간에 존재하거나 존재했던 장소에 관한 정보로서 전기통신설비 등을 이용해 측위된 정보다. 따라서 현재의 고정 부동산 주소 입력·저장만으로는 위치정보법상 위치정보 또는 개인위치정보 처리에 해당할 가능성이 낮고, 개인위치정보를 대상으로 하는 위치기반서비스사업 신고 필요성도 낮다는 것이 1차 판단이다.

컨설팅은 무료이고 신청대상에 위치정보 산업 진출 예정 스타트업도 포함되지만, 현재 제품 범위에는 위치정보 시스템 구축·위치기반서비스 진출 계획이 확인되지 않는다. 따라서 지금 3회 이상 컨설팅을 신청하는 실익은 낮다. 다만 `현재 위치 주변 매물`, 통근거리 기반 추천, 위치 공유, 이동경로 또는 단말 위치 기반 안전 기능을 제품 로드맵에 확정하면 신청 가치가 즉시 생긴다.

## 3. 현재 데이터 흐름과 법 적용성

| 단계 | 저장소 증빙 | 판단 |
| --- | --- | --- |
| 주소 검색 | `components/ui/address-search.tsx`가 `Daum Postcode` script를 로드하고 도로명/지번 주소를 반환 | GPS·단말 위치 측위 아님 |
| 주소 입력 | `components/landlord/property-form.tsx`에서 검색 주소 및 상세주소 입력 | 고정 부동산 식별정보 |
| 저장 | `app/api/landlord/properties/route.ts`가 `address`, `address_detail`, `region`을 `properties`에 저장 | 계정과 결합된 주소는 개인정보 보호 관점 검토 필요 |
| 검색·추천 | `app/api/properties/route.ts`, `lib/ai-matching.ts`가 주소 문자열·지역을 검색/매칭 | 위치정보법상 측위정보 이용 증거 없음 |
| 단말 위치 | `next.config.js`의 `Permissions-Policy`가 `geolocation=()`으로 차단 | 웹에서 위치 API를 쓰지 않는 방향과 일치 |
| 좌표·이동경로 | `latitude`, `longitude`, `getCurrentPosition`, `watchPosition` 구현 미검출 | 현행 개인위치정보 처리 가능성 낮음 |

법적 분기점은 주소라는 단어 자체가 아니라, **이동성이 있는 개인·물건의 특정 시점 위치를 통신설비로 측위했는지**와 이를 개인과 결합해 서비스에 이용하는지다. 주택 좌표를 향후 추가하더라도 고정 부동산 위치만 다룬다면 위치정보법 적용성은 여전히 낮을 수 있으나, 사용자 현재 위치와 결합한 주변 검색·추천부터는 별도 검토가 필요하다.

## 4. 규제·정책 갭

### 현재도 보완할 개인정보 고지

`app/privacy/page.tsx`의 공개 방침에는 매물 주소·상세주소·계약 대상 주소, 수집 목적, 보유기간, 공개 범위가 명시되어 있지 않다. `Daum Postcode` 외부 script 사용에 따른 데이터 흐름과 제3자 제공/처리위탁 또는 국외이전 해당 여부도 문서상 확인되지 않는다.

위치정보법 신고 대상이 아니더라도 다음은 별도로 정리해야 한다.

1. 매물 주소와 상세주소를 개인정보 처리 항목·목적·보유기간 표에 반영
2. 공개 목록에서는 상세주소를 최소화하고 권한별 표시 범위를 명시
3. `Daum Postcode` SDK가 실제로 수신하는 검색어·접속정보와 사업자 역할을 약관 기준으로 확인
4. 매물 삭제·회원 탈퇴 시 주소 및 관련 로그 파기 경로 검증
5. 계약 리포트·공유 카드에서 상세주소 노출 수준과 만료·철회 정책 검증

### 위치기반 기능 도입 시 새로 필요한 검토

개인위치정보를 이용하는 기능을 도입한다면 출시 전에 최소한 아래를 확인한다.

- 위치기반서비스사업 신고 또는 소상공인·1인 창조기업 특례 적용 여부
- 서비스별 수집·이용·제공 목적과 동의 화면
- 위치정보 이용약관 및 개인위치정보 처리방침 공개
- 위치정보 보호를 위한 관리적·기술적 조치와 접근권한·로그·파기 설계
- 동의 철회, 일시중지, 열람·고지·정정 요구 기능
- 제3자 제공 시 통보 및 위치정보 수집·이용·제공사실 확인자료 관리

## 5. Go/No-Go 기준

### 현재: No-Go

- 제품이 개인 또는 이동 물건의 측위정보를 수집·이용하지 않는다.
- 주소 문자열 기반 매물 검색만으로는 전용 위치정보 컨설팅의 핵심 범위와 거리가 있다.
- 먼저 개인정보처리방침의 주소 처리 고지를 정비하는 편이 실행 우선순위가 높다.

### 아래 중 하나 확정 시: Go로 전환

- 사용자 현재 위치 기반 주변 매물 탐색
- 출퇴근·생활권 추천을 위한 단말 위치 또는 이동경로 처리
- 임대차 안전을 위한 실시간 위치 공유·체크인
- GPS가 부착된 이동 물건 또는 개인 위치 데이터 제휴
- 지도 SDK/API가 개인의 시점별 위치를 서버로 전달하는 설계

전환 시 컨설팅 질문은 `서비스 분류 및 신고`, `동의·약관`, `SDK/API 데이터 흐름`, `보호조치`, `AI 추천에 사용하는 위치 데이터 최소화`의 다섯 축으로 구성한다.
