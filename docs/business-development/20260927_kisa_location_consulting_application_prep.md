## 3. 실측으로 뒤집힌 추측 3건

### (1) 희망 컨설팅 분야는 단일선택이다 — 질문 배치를 바꿨다

`ctype`은 16개 선택지를 가진 **radio**다. 체크박스가 아니다. 한 번의 신청에 **한 분야만** 고를 수 있다.

```
경영   A1 A2 A3
법/제도 B1 위치정보법, 정보통신망법 관련 사항
        B2 특허권, 상표권 등 지식재산권 관련 사항
        B3 위치정보사업을 수행하기 위한 등록, 신고 및 법적 애로사항
기술   C1 C2 C3 C4
투자유치 D1 D2 D3
AI     E1 E2 E3
```

DOW-1273의 쟁점 5개는 B1과 B3에 걸쳐 있다. 쟁점 2(위치기반서비스사업 신고·특례)는 B3, 쟁점 1·3·4·5는 B1이다.

**판단: `B1`을 선택한다.** 근거는 두 가지다.

1. 쟁점 5개 중 4개가 B1이고, 나머지 하나(신고 여부)는 **B1 쟁점 1의 결론에 종속**된다. 지문 채집이 개인위치정보 처리가 아니면 신고 논의 자체가 사라진다. 순서상 B1이 먼저다.
2. 컨설팅이 **3회 이상**이므로 1회차 B1 결론 이후 회차에서 신고·절차를 다룰 수 있다. 분야를 신청 단계에서 쪼갤 필요가 없다.

신고 쟁점은 버리지 않고 `memo2`에 "후속 회차 예정 논점"으로 명시해 매칭 단계에서 행정사 동석 가능성을 열어 둔다.

### (2) 필수값 검증은 동의 체크박스 하나뿐이다 — 오제출 위험

JS 전체를 덤프한 결과 검증 로직은 이것뿐이다.

```js
if (f.chk.checked) { document.frm.action = "sub02_proc.asp"; document.frm.submit(); }
else alert("개인정보 수집 및 이용에 대한 안내를 모두 동의해 주세요.");
```

라벨의 `*` 는 **클라이언트에서 강제되지 않는다.** 즉 동의 체크 + 버튼 클릭 한 번으로 미완성 신청서가 그대로 접수된다. 서버측(`sub02_proc.asp`) 검증 여부는 확인할 수 없다 — 확인하려면 실제 제출이 필요하고, 그것은 승인 없이 하지 않는다.

**운영 결론: 이 폼은 "임시저장 후 검토"가 불가능하다.** 문안을 이 문서에서 완성한 뒤 한 번에 붙여 넣는다. 화면에서 작성하며 다듬는 방식은 금지한다.

### (3) 게시판 답변일이 전부 비어 있고, 최근 접수가 4개월 전이다

공개 게시판 최근 10건(2025-10-22 ~ 2026-05-26)의 `답변일` 컬럼이 **10건 전부 공백**이다. 컬럼 자체는 존재한다(헤더: 번호·제목·작성자·등록일·답변일·조회수).

이것을 "답변을 주지 않는다"로 읽으면 과잉 해석이다. 답변이 비공개로 전달되고 컬럼이 미사용일 수 있다. 다만 **최근 접수 기록이 2026-05-26 이후 4개월간 없다**는 점은 별개의 신호다. 2026-08-24 검토가 기록한 `상시 접수(연중)`가 현재도 유효한지는 요강 페이지만으로 확정되지 않는다 — 페이지에 접수기간 표기 자체가 없다.

**해소 방법: 운영사무국 02-3786-0546 유선 확인.** 외부 발신이므로 보드 승인 대상이며, 10-10 승인 상신에 신청 실행과 함께 묶는다. 확인 질문 2개는 6장에 있다.

## 4. 데이터 흐름도 — 현재 / PoL 결합 후

### 4.1 현재 (2026-09-27 저장소 실측)

```
[사용자] ──주소 문자열 입력/검색──▶ Daum Postcode SDK (외부)
                                        │ 도로명·지번 반환
                                        ▼
                            properties.address / address_detail / region
                                        │
                                        ▼
                     매물 검색·AI 매칭 (문자열·지역 단위)

[단말 GPS] ──✕ 차단── next.config.js:87  Permissions-Policy: geolocation=()
```

**측위 데이터가 흐르는 경로가 없다.** 2026-09-27 재확인 결과:

- `next.config.js:87` → `camera=(), microphone=(), geolocation=()` 그대로 유지
- `getCurrentPosition` / `watchPosition` / `expo-location` 자사 소스 검출 **0건** (웹 `app`·`lib`·`components`, 모바일 `mobile/app`·`src`·`lib`·`components`, `mobile/package.json`). 검출된 파일은 전부 `node_modules`·Android 빌드 산출물
- `longitude` 컬럼 자사 코드·마이그레이션 검출 **0건**

따라서 2026-08-24의 "현재는 위치정보법 적용 가능성 낮음" 1차 판단은 **오늘도 유효하다.** 한 달 전 문서를 그대로 인용한 것이 아니라 다시 측정했다.

### 4.2 PoL 결합 후 (DOW-1153 설계안 기준)

```
[임차인/등록자 단말]
   │ LTE·WiFi·BLE 신호 지문 채집          ◀── 쟁점 1: 이것이 개인위치정보 처리인가
   ▼
ETRI PoL SDK
   │ 지문 → 위치증명(proof)               ◀── 쟁점 3: 절대좌표 미보관·해시 대조 설계의 법적 취급
   ▼
입주해 서버                                ◀── 쟁점 4: 처리위탁 vs 제3자 제공
   │
   ├─ trust_source_registry (code=etri_pol, source_type=partner_api,
   │                         legal_basis=위치정보 수집·이용 동의,
   │                         retention_days=최소, allowed_fields={presence_at_property})
   │
   ├─ trust_evidence_nodes (object_hash=증명 해시, observed_at=측위시각,

   ▼

```

**설계 의도: 절대좌표를 저장하지 않고 증명과 해시만 보관한다.** 이 설계가 법적 취급을 실제로 달리하는지가 컨설팅의 핵심 질문이다(쟁점 3). 이 답에 따라 11-09 PoC의 데이터 설계가 바뀐다.

- `trust_source_registry.privacy_risk` — 원천별 프라이버시 민감도

> **배경**
>
> 임대차 정보 플랫폼을 준비하는 예비창업 단계입니다. 현재 서비스는 고정된 주택의 도로명·지번 주소만 저장·검색하며 단말 GPS·이동경로를 수집하지 않습니다(브라우저 위치 권한도 차단 상태입니다).
>
> 2026-11월 ETRI의 위치인증(PoL) 기술을 활용해, 매물 등록자가 해당 주소지에 실제로 있었음을 증명하는 `현장확인` 기능의 PoC를 시작할 예정입니다. 단말이 주변 LTE·WiFi·BLE 신호 지문을 채집해 위치증명을 발급받고, 서비스는 **절대좌표를 저장하지 않고 증명과 해시만 보관**하는 설계를 검토 중입니다. 협약 체결 전에 법적 성격을 확인해야 데이터 설계를 되돌리지 않을 수 있어 문의드립니다.
>
> **질문 1 (서비스 분류·신고)**
> 위와 같이 단말의 LTE·WiFi·BLE 신호 지문을 채집해 위치를 증명하는 처리가 위치정보법상 개인위치정보 처리에 해당합니까. 해당한다면 위치기반서비스사업 신고 대상이며, 예비창업자·1인 창조기업·소상공인 특례로 신고 시점을 늦추거나 면제받을 수 있습니까. 신고가 필요한 경우 PoC 단계(비공개 시범)와 정식 출시 중 어느 시점부터 의무가 발생합니까.
>
> **질문 2 (좌표 미보관 설계의 법적 취급)**
> 절대좌표(위도·경도)를 저장하지 않고 신호 지문의 해시만 대조·보관하는 설계가, 좌표를 저장하는 설계와 법적으로 달리 취급됩니까. 해시가 특정 장소·개인과 재결합 가능하다면 여전히 개인위치정보로 보아야 합니까. 이 구분이 성립한다면 이용약관·처리방침에는 어떻게 기재해야 합니까.
>
> **질문 3 (SDK·API 데이터 흐름의 사업자 구분)**
> 외부 기관(ETRI)의 SDK가 측위를 수행하고 그 결과가 당사 서버로 전달되는 구조에서, 기관과 당사의 관계는 처리위탁입니까 제3자 제공입니까. 이 구분에 따라 기술사용권·협약 문안에 반드시 포함해야 할 조항은 무엇입니까. 당사가 위치정보사업자와 위치기반서비스사업자 중 어디에 해당하는지도 함께 확인 부탁드립니다.
>
> **질문 4 (동의·철회·보호조치)**
> 위치증명 발급에 필요한 동의를 수집·이용·제3자 제공으로 분리해 받아야 합니까. 동의 철회·일시중지 요구가 있을 때 이미 발급된 증명과 그에 기반해 부여된 표시(배지)는 어떻게 처리해야 합니까. 위치정보 수집·이용·제공사실 확인자료의 보관 항목·기간과, 당사가 갖춰야 할 관리적·기술적 보호조치의 최소 범위를 알려주십시오.
>
> **질문 5 (추천·점수 산정에서의 최소수집)**
> 위치증명을 매물 신뢰도 점수와 추천 순위 산정에 활용할 때, 목적 범위와 최소수집 원칙상 허용되는 활용 범위는 어디까지입니까. 증명의 보관기간을 최소화하면서도 이력 기반 신뢰도를 유지하려면 어떤 설계가 적법합니까.
>
> **후속 회차 예정 논점**
> 위 결론에 따라 등록·신고 실무 절차(신청서·구비서류·처리기간)를 다음 회차에서 다루고자 합니다. 가능하면 행정사 자문을 함께 받을 수 있는지 확인 부탁드립니다.
