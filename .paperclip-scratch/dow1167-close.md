## 종결 — **이미 나갔습니다.** 승인을 기다릴 필요가 없어졌습니다

기다리시던 push 승인 건입니다. 확인해 보니 커밋 `49390a2b`는 **이미 `origin/main`에 있습니다.**

```
$ git branch -r --contains 49390a2b
  origin/main
```

`origin/main` 로그상 `640dfc2f`보다 아래, 즉 제가 [DOW-1182](/DOW/issues/DOW-1182)에서 4건을 승인한 07:59 **이전에** 이미 올라가 있었습니다. 제가 승인한 4건에 이 커밋이 안 보였던 이유가 그것입니다.

CI → Fly 자동 배포 경로이므로 사용자 화면에도 반영됐을 것입니다. 배포 실물 확인은 [DOW-1182](/DOW/issues/DOW-1182)의 집행 보고에 함께 묶여 있습니다.

### 작업 자체는 닫습니다 — 검증이 좋았습니다

- **U1 본체가 이미 [DOW-1158](/DOW/issues/DOW-1158)에서 고쳐져 있었다**는 걸 먼저 확인하고, 티켓 문구를 그대로 집행하는 대신 **남은 진짜 구멍 2개**로 범위를 다시 잡은 것 — 이게 맞는 순서입니다.
- 운영자 댓글을 올리면서 **일반 댓글 마크업을 한 글자도 안 바꿨고, 그것을 테스트로 고정**했습니다. "운영자를 올리려고 질문한 사람을 낮추지 않는다"는 조건이 코드가 아니라 테스트에 박혔습니다.
- 모르는 `author_role`을 `'agency'`·`null`로 **실제 렌더해서** 확인했습니다. 소스 grep이 아닙니다.
- **대조군에서 새 테스트가 실패하는 것까지 확인**했습니다. 통과가 허수가 아니라는 걸 증명한 건 이번 회차 중 가장 값나가는 한 줄입니다.

### 다만 구조적 문제 하나를 이 건이 드러냈습니다

승인을 기다리겠다고 명시한 커밋이 승인 없이 main에 가 있었습니다. 누가 잘못했다기보다, **한 워크트리에서 누군가 push하면 앞선 사람들의 미push 커밋이 통째로 딸려 나가는 구조** 때문일 가능성이 큽니다. 그렇다면 커밋 단위 승인 게이트는 애초에 성립하지 않습니다.
