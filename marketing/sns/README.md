## 왜 이걸 하고 있나

인스타·스레드에 올려도 반응이 없고 신청이 0에 가까웠는데, 어디서 막히는지 구분할 수단이 없었다.
그래서 (1) 계측을 먼저 깔고 (2) 콘텐츠 종류를 "제품 소개"에서 "임대차 정보"로 바꾸고
(3) 1차 타깃을 세입자가 아니라 **임대인·중개사**로 잡았다.

임대인·중개사를 먼저 미는 이유: 세입자용 전세사기 콘텐츠는 포화라 신생 계정이 이기기 어렵고,
공급측이 "Trust Card 있으세요?"라고 묻기 시작하면 세입자는 따라 들어온다(양면 시장 콜드스타트).
중개사는 수가 유한해서 오프라인 접촉도 가능하다.

## 디자인 캔버스를 다시 만들려면

`marketing/sns/canvas/`의 `.dc.html` 파일을 고친 뒤, Claude Code에서 `/design` 스킬로 다시 씨딩하면 된다.
아트보드 16장(`Main`, `Deungi2~8`, `Landlord1~6`, `ReelsCover1~2`)과 `canvas.json`을 전부 넘겨야 하고,
**기존 캔버스와 같은 URL로 갱신하려면 위 표의 캔버스 URL을 함께 넘겨야 한다.** 안 그러면 별도 캔버스가 새로 생긴다.

디자인 규격
- 캐러셀 슬라이드 1080×1350 (4:5), 패딩 `120px 90px` → 실사용 폭 900px
- 릴스 커버 1080×1920 (9:16), 위 250px·아래 450px은 앱 UI에 가려지므로 비움
- 색: 바탕 네이비 `#0C2247`, 강조 앰버 `#E9A23B`, 글자 흰색
- 서체: Gothic A1 (Pretendard가 웹폰트로 안 올라가서 대체). PNG로 내보내면 시스템 한글 폰트로 떨어질 수 있음
- **한글 제목은 88px을 기본으로.** 96px로 하면 열 글자 넘는 줄이 900px을 넘겨 깨진다. 들여쓰기가 있으면 그만큼 더 줄여야 함

## 계측 — 이미 프로덕션에 반영됨

커밋 `7dbc64f6`, 마이그레이션 041 적용 완료(applied=46 pending=0).

- 랜딩 방문은 `analytics_events`에 `page_view`로 쌓인다 (`properties.path`, `properties.utm_source`)
- 신청자는 `waitlist.utm_source / utm_medium / utm_campaign / referrer_host`에 유입 경로가 남는다
- 채널별 방문→신청→전환율은 관리자 API `GET /api/admin/waitlist` 응답의 `sources`에서 본다

**링크에 UTM을 안 붙이면 전부 `direct`로 뭉쳐서 채널 비교가 불가능하다.**

| 위치 | 붙일 주소 |
| --- | --- |
| 스레드 | `ipjuhae.com/?utm_source=threads` |
| X | `ipjuhae.com/?utm_source=x` |
| 인스타 프로필 | `ipjuhae.com/?utm_source=ig_bio` |
| 릴스 설명·댓글 | `ipjuhae.com/?utm_source=ig_reel` |
| 유튜브 쇼츠 | `ipjuhae.com/?utm_source=shorts` |

## 지켜야 할 선

- **사용자 수를 부풀리지 않는다.** 현재 사전 신청 1명. 이 서비스는 신뢰를 파는데 한 번 들키면 끝난다
- **차별 소지를 만들지 않는다.** 세입자를 학력·직장·국적·가족구성으로 거르는 이야기는 안 한다.
  제품도 그렇게 설계돼 있고(학력·직장명 안 봄, 소득은 월세 대비 비율만), 그게 차별점이다
- **확인 안 된 숫자를 쓰지 않는다.** 원고에서 등기부 발급 수수료 금액과 "근저당 70%" 기준선을 일부러 뺐다.
  넣으려면 출처를 확인하고 함께 적을 것
- **법률 조언처럼 단정하지 않는다.** "이렇게 하면 안전합니다" 대신 "확인해야 할 항목"으로 쓴다
- 카페·커뮤니티 무단 홍보 금지, 실제 피해자 사례 무단 사용 금지, 팔로워 구매 금지
